[P1] Restore the staging-directory cleanup trap — snapshot.sh:77-77

[P2] Escape values interpolated into the remote ssh command — lib/common.sh:97-99
  `$BACKUP_REMOTE_DIR` and `$name` (which contains the `--label` value verbatim) are pasted into a single-quoted remote shell string with no escaping, so a value containing `'` both breaks the command and executes arbitrary commands on the replica host. Passing the values as `ssh` arguments and referencing them as `"$1"`/`"$2"` inside the remote script, or running them through `printf %q`, removes the sink.

[P2] Remote `cat` writes directly to the final name, so drops do leave partials — lib/common.sh:89-92

If the stream dies mid-transfer, the replica keeps a truncated `.tar.gz` under the real archive name, indistinguishable from a good one — the local run aborts and never publishes, so the replica is the only copy of that timestamp. Writing to a temporary name and renaming on success (`cat > "$tmp" && mv "$tmp" "$final"`) would deliver the guarantee the comment describes.

`★ Insight ─────────────────────────────────────`
- The two P0s share a shape worth naming: **a producer changed, a consumer didn't**. The manifest gained a column in `snapshot.sh` and `prune.sh` kept reading three fields; the force flag became the string `"0"` and the test kept asking only "is it non-empty?". In both cases the code stays syntactically valid and exits 0, which is why they survived to review — shell has no type checker to catch a widened record or a truthiness mismatch.
- `[ "$x" ]` in POSIX shell is a one-argument test that asks *is this string non-empty*, not *is this value true*. Any sentinel that spells "off" as a printable character — `"0"`, `"false"`, `"no"` — passes it. This is the single most common bash boolean bug, and the fix is always to compare explicitly against the enabled value.
- The dropped `trap` illustrates a hazard specific to refactoring: moving `mktemp -d` into a helper function moved the *allocation* but left the *deallocation* behind. Cleanup registered via `trap` has to live in the scope that owns the exit, so extracting a resource-acquiring helper means the trap either goes with it or gets re-established at the call site.
