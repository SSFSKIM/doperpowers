[P2] Read the new revision back instead of using `save_document`'s return value — /private/var/folders/c1/l4z5k02n2779byvnymzxsvth0000gn/T/review-bench.woIagz/app.py:166-174

`★ Insight ─────────────────────────────────────`
- The P0 and P2 findings share a root cause worth naming: **the change moved a contract but not every consumer of it.** Converting authorization to decorators means the security property now lives in one line above each handler, so a wrong decorator is silently valid Python — the type checker has nothing to object to. Same with `save_document` changing its return meaning from "revision" to "row count": both are `int`, so the caller kept compiling while quietly emitting the wrong ETag.
- That suggests a structural defense rather than just three patches: make the decorator choice checkable (a test that asserts every handler touching `list_tenants()` is admin-gated) and make the store's return type distinguishable (a `Revision` NewType, or returning the saved record rather than a bare integer). Bugs that survive review are usually the ones where two different concepts share a representation.
- The pagination bug is a different species — a classic inclusive/exclusive boundary slip. Note that the variable was *named* `last`, which invites `+ 1` thinking; naming it `end` or `stop` matches Python's half-open slice convention and makes the correct code look correct.
