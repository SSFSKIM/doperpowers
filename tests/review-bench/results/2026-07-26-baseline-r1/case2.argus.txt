`★ Insight ─────────────────────────────────────`
- Two of the three findings share a root cause pattern worth naming: a **unit migration** (dollars → integer cents) is a change to a function's *contract*, not just its body. TypeScript can't catch it because both the old and new return types are `number` — the compiler sees no difference between 950 cents and 9.50 dollars. A branded type (`type Cents = number & { readonly __brand: "Cents" }`) would have turned the `quickEstimate` bug into a compile error at zero runtime cost.
- The dropped validation is a classic **refactor-by-extraction** hazard: when logic moves from `quoteShipment` into a new `buildBreakdown`, guards that lived in the old function's preamble are easy to leave behind, and the surrounding `try`/`catch` gets deleted as "dead" once nothing throws — which is exactly the symptom, not the proof.
- The `<=` → `<` change in `tierFor` is the kind of edit that looks like a normalization cleanup but is a pricing change. Boundary semantics documented in prose (README, doc comments) and not pinned by a test at the exact boundary value are effectively unenforced.
