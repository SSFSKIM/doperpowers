`★ Insight ─────────────────────────────────────`
Two of these findings share a root cause worth naming: **shell tests that look like booleans but aren't.** `[ "$force" ]` is a one-argument test that asks "is this string non-empty?", not "is this true?" — so the string `"0"` passes it. This is one of the most common POSIX shell bugs, and it's invisible in review unless you trace what the caller actually passes. The same class of trap appears in `[ "$flag" = "false" ]` style checks where the caller sends an empty string.

The P0 is a different and more structural class: **a serialization format changed on the writer side without a corresponding reader change.** Because `read -r` in shell silently absorbs extra leading fields (the last variable soaks up the remainder of the line), the mismatch produces no error — just wrong values that flow into a plausible-looking "missing archive, skipping" log line. Formats crossing a process boundary benefit from a version marker or a field-count assertion so the reader fails loudly rather than degrading quietly.
