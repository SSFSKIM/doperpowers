`★ Insight ─────────────────────────────────────`
- **Unit migrations are call-site problems, not type problems.** Switching money from dollars to integer cents is the right call (floating-point dollars accumulate rounding error), but because both representations are plain `number`, the compiler cannot flag a missed conversion. The `quickEstimate` bug is exactly what a branded type (`type Cents = number & { readonly __brand: "Cents" }`) exists to prevent — it costs one line and turns a silent 100x pricing bug into a compile error.
- **Boundary conditions belong in tests, not only in doc comments.** The `<=` → `<` flip in `tierFor` is a one-character change that no type system catches and no runtime error surfaces; the invariant was written down in a comment and the README, but nothing executable enforced it. Tier lookups are a textbook case for table-driven tests over exact boundary weights (1, 5, 20 kg).
- **Deleting a `throw` and its `catch` together looks tidy in a diff.** Removing the `RangeError` from `quoteShipment` and the `try`/`catch` in `handleQuote` is self-consistent, so the change reads as clean refactoring — but validation at the system boundary is the one place where checks are not speculative, because the input comes from outside your trust boundary.
