`★ Insight ─────────────────────────────────────`
- All three findings share one root cause pattern: a **unit-of-measure refactor** (dollars → integer cents) that changed a function's return contract but not every caller. `handleQuote` was updated to convert at the boundary; `quickEstimate` was missed. This is exactly why unit changes benefit from a nominal type (e.g. `type Cents = number & { __brand: "cents" }`) — the compiler then catches the missed call site instead of shipping a 100x pricing bug.
- The second and third findings are both cases where **prose documentation stayed put while code moved**. The README and the `maxKg` doc comment are unchanged in the diff, so they act as an oracle: any behavior that now contradicts them is either a bug or an undocumented intentional change. Reading unchanged docs alongside a diff is a cheap, high-yield review technique.
- `NaN` deserves special note: it defeats naive validation twice over. `typeof NaN === "number"` passes a type check, and `JSON.stringify({ total: NaN })` silently produces `"total": null` rather than throwing — so the bad input surfaces to the client as a missing field rather than an error.
