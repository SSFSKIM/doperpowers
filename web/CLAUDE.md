# web/

A path here is named from `web/` when it is the plugin's own file; `docs/`, `scripts/` and `tests/…` paths are the repository's.

A fifth plugin in this marketplace (versioned on its own: `scripts/bump-version.sh --plugin web`), the fetch tool `mcp__web__fetch`: a page saved as a clean markdown file in the shape Obsidian Web Clipper produces, its images beside it, in a cache every session on the machine shares, and a reply in the shape the page needs. Design and decision record: `docs/doperpowers/specs/2026-10-25-web-fetch-design.md`.

It is two halves because a mod has no Node and no DOM:

- `clipper/` is a TypeScript package (Defuddle over linkedom, a guarded HTTP client, the headless-Chromium render behind a filtering proxy, the cache) built by esbuild into `bin/clip.mjs`, which is committed so a session installs nothing and needs only `node` 20+. After changing `clipper/src`, run `npm run build` there and commit the bundle with it; the `web` gate fails when the committed bundle is not what the source and lockfile build. `node bin/clip.mjs fetch|numbered|prune` is its CLI (I1 in the design), usable from Bash by any agent; the engine puts a plugin's `bin/` on its sessions' Bash `PATH`.
- `hooks/mods/` is the mod. `fetch.tsx` holds everything that takes `$`: it registers the tool at every session's start, interactive or headless, with `isDeferred: false` (its schema in the prompt's tool list from the first turn), runs the clipper through `$.process.run` (180 s, 30 s past the clipper's own deadline), asks `haiku` through `$.model.complete` when the call has a `prompt` (the page's text from `clip.mjs numbered`, never `$.fs.read`, which refuses files over 4 MiB), appends each summary call's usage to `<cache root>/usage.jsonl`, and starts `clip.mjs prune` unawaited when `<cache root>/.pruned` is a day old. `reply.ts` is every reply's text (R1 the page, R2 the outline, R3 the answer, R4 the error, and the non-text kinds), a pure function of the clipper's result; `summary.ts` is the summary's fixed text and limits. A subagent's call is served like the main session's.

A failed fetch is returned as `{ deny }`, which the model reads as an error result, `<tool_use_error>fetch failed: …</tool_use_error>`, with no permission wording; the registration's `.catch` turns a step that throws (a refused model request) into the same. The tool's description, the reply shapes and the summary's system text are agent-facing behavior: change them only with the reason in the design's Decision Log, the evals being their pressure test.

`WEB_ALLOW_HOSTS` (comma-separated `host:port`) exempts local test servers from the network boundary; it is a test seam, not a setting. `WEB_CACHE_DIR` moves the cache; `WEB_CHROME` names the Chromium binary, `none` turning rendering off.

Tests: `tests/run.sh` is the `web` gate (the clipper's `npm test`, the bundle check, then `tests/mods/run.sh`, which stages the manifest, hooks and mod tests in a folder of their own, since `claude plugin test` would otherwise sweep the clipper's `node --test` files). The gate runs with `WEB_CHROME=none`: the rendering tests skip there, and the egress tests that decide whether rendering ships run on a Mac with the Playwright headless shell (`cd clipper && npm test`). `tests/mods/typecheck.sh` typechecks the mod through `hooks/mods/tsconfig.json`; `web/tsconfig.json` is the engine's, written when a session loads the plugin, and ignored.
