# web/

A path here is named from `web/` when it is the plugin's own file; `docs/`, `scripts/` and `tests/…` paths are the repository's.

A fifth plugin in this marketplace (versioned on its own: `scripts/bump-version.sh --plugin web`), the fetch tool `mcp__web__fetch`: a page saved as a clean markdown file in the shape Obsidian Web Clipper produces, its images beside it, in a cache every session on the machine shares, and a reply in the shape the page needs. Design and decision record: `docs/doperpowers/specs/2026-10-25-web-fetch-design.md`.

It is two halves because a mod has no Node and no DOM:

- `clipper/` is a TypeScript package (Defuddle over linkedom, a guarded HTTP client, the headless-Chromium render behind a filtering proxy, which also draws SVG images as PNGs, the cache) that saves an HTML page's article as `page.md` and, when it adds to it, the whole page beside it as `full.md` (its images left as links), built by esbuild into `bin/clip.mjs`, which is committed so a session installs nothing and needs only `node` 20+. After changing `clipper/src`, run `npm run build` there and commit the bundle with it; the `web` gate fails when the committed bundle is not what the source and lockfile build. `node bin/clip.mjs fetch|numbered|prune` is its CLI (I1 in the design), usable from Bash by any agent; the engine puts a plugin's `bin/` on its sessions' Bash `PATH`.
- `hooks/mods/` is the mod. `fetch.tsx` holds everything that takes `$`: it registers the tool at every session's start, interactive or headless, with `isDeferred: true` (behind `ToolSearch`, as the engine defers `WebFetch`: a session sees its name, and loads its schema before the first call), runs the clipper through `$.process.run` (180 s, 30 s past the clipper's own deadline), asks `haiku` (or the model `WEBFETCH_MODEL` names) through `$.model.complete` when the call has a `prompt` (the page's text from `clip.mjs numbered`, never `$.fs.read`, which refuses files over 4 MiB), and once more over `full.md` when the answer over the article opens `Not on this page:`, appends each summary call's usage to `<cache root>/usage.jsonl`, and starts `clip.mjs prune` unawaited when `<cache root>/.pruned` is a day old. `reply.ts` is every reply's text (R1 the page, R2 the outline, R3 the answer, R4 the error, and the non-text kinds), a pure function of the clipper's result; `summary.ts` is the summary's fixed text and limits. A subagent's call is served like the main session's.

A failed fetch is returned as `{ deny }`, which the model reads as an error result, `<tool_use_error>fetch failed: …</tool_use_error>`, with no permission wording; the registration's `.catch` turns a step that throws before the page is in hand into the same. A call the user interrupts kills the clipper; after send now its reply opens `fetch interrupted:`, saying neither the site nor the plugin failed (after Esc the engine puts its own text in the result). The clipper remembers a failure the site or the network gave in the entry's `.failed.json` and answers the URL from it for 5 minutes unless `refresh` is set, so a URL that keeps failing is not fetched again until then. A saved copy answers as it stands for 5 minutes after its fetch or its last check; past that the fetch is its check, and the copy stands when the site shows it unchanged (a 304 to its validators, the same body, or the same extracted text), the check's time recorded in the entry's `.checked.json`; a check the site fails gives the copy with why. A summary request that throws is a failed summary, not a failed fetch: the page comes back (R1 or R2) opening with why. The tool's description, the reply shapes and the summary's system text are agent-facing behavior: change them only with the reason in the design's Decision Log, the evals being their pressure test.

`WEB_ALLOW_HOSTS` (comma-separated `host:port`) exempts local test servers from the network boundary; it is a test seam, not a setting. `WEB_DENY_HOSTS` (comma-separated hosts, `*.example.com` for every host under one) is the owner's deny list: the boundary refuses those hosts before any request, the agent's URL before its cached copy too, whatever `WEB_ALLOW_HOSTS` says. `WEB_CACHE_DIR` moves the cache; `WEB_CHROME` names the Chromium binary, `none` turning rendering off; `WEBFETCH_MODEL` names the model that answers a `prompt` in place of `haiku` (the mod reads it; `$.env.get` takes the name written out).

`evals/` is the eval suite that gates the switch-over from `WebFetch` (the design's "The evals"; I4 its file formats): `tasks.json` (40 tasks, 2 `dev` and 3 `final` per category; the final ones are never tuned against) and `tasks-reserve.json` (16 more finals, run only when criterion 1 is inconclusive); `run.py` runs each task in configuration A (`WebFetch` only) and B (`mcp__web__fetch` only), `claude -p` on `sol` at `xhigh` in a temporary `HOME` holding only the gateway's keys (`harness.py`), and grades each run with `grade.py` (`sol` at `xhigh` since the hard set; the first suite was graded by opus, which `--grader opus` repeats; no tools, the answer masked); `report.py` judges a run folder against the pass criteria. `tasks-hard.json` is the harder set (board #132), built so `WebFetch` can fail and a difference can show: its tasks were screened by running configuration A alone (`run.py --arms A`), whose folder `report.py` reports as a screening round. A task with `"search": true` names no URL, and both configurations get `search_mcp.py`'s `web_search`, an MCP server that makes `WebSearch`'s request on haiku, since `WebSearch` on `sol` fails through the gateway. Both configurations also load `deny-readers/`, an eval-only plugin whose mod denies a fetch through a third-party reader or proxy (the hosts are in `deny_readers.py`): a settings hook cannot, as the engine runs none for a mod's tool. Python 3 standard library, run with `python3 -I`; the runs go to `evals/runs/` (ignored) and resume. The suite runs on a Mac, where the gateway listens on loopback; it spends real model calls, so it is never part of the gate, and `run.py --pilot` projects a round's cost first.

Tests: `tests/run.sh` is the `web` gate (the clipper's `npm test`, the bundle check, then `tests/mods/run.sh`, which stages the manifest, hooks and mod tests in a folder of their own, since `claude plugin test` would otherwise sweep the clipper's `node --test` files, then the eval scripts' unit tests, which make no model call). The gate runs with `WEB_CHROME=none`: the rendering tests skip there, and the egress tests that decide whether rendering ships run on a Mac with the Playwright headless shell (`cd clipper && npm test`). The render drives Chromium over the DevTools protocol on a pipe (`clipper/src/cdp.ts`); its protocol handling is tested everywhere against a stand-in browser, `clipper/test/fixtures/fake-chrome.mjs`. `tests/mods/typecheck.sh` typechecks the mod through `hooks/mods/tsconfig.json`; `web/tsconfig.json` is the engine's, written when a session loads the plugin, and ignored.
