## Brief

**Purpose.** sminos is about to treat the thread that made a devcloud VM as the VM's owner: such a thread is not retired, and not ended after three days stopped, while the VM exists (the spec's D4). sminos keeps no copy of who owns what; it asks devcloud. That question has to be one whose "none" can be trusted, because a wrong "none" ends the owner of a VM that goes on costing money. Today's `devcloud vm ls` cannot be that question: it skips an account it cannot use and a provider listing that failed, and reports what is left with exit 0 (`Context.usable`, `Context.fleet` in `devcloud/driver/context.py`; `ops.ls` in `devcloud/driver/ops.py`).

**What done looks like** (the spec's DV section and contract X9 bind; read both, and D4's paragraph on ownership):

1. A command of the driver answers, for one or more names of a creator, which VMs they own. A name is a creator tag as descriptors hold it (`@short`, `@alias#short`, `@alias`, `@project/alias`: `_CREATOR` in `devcloud/boot/devcloudlib/descriptor.py`) or a session's short id; a VM matches when its creator tag equals a given tag or carries a given short id.
2. Its answer, in a form a program reads, is exactly one of: the VMs that match (each with what a caller needs to name it to a person: at least its name and provider or account); none, having listed every configured account in full; or unknown, naming each account that could not be used and each provider whose listing failed. A provider failure or an unusable account never yields "none". When some VMs matched and something else could not be listed, the answer carries both: the caller treats a match as owning whatever else is unknown.
3. The three answers are told apart without parsing prose (the exit code, a field, or both: your call, stated in this ledger).
4. On a machine where the driver does not run (a devcloud host, where every `vm` command exits 6 today), nothing changes: the caller does not ask there (X9).
5. Tests cover: a match by tag and by short id; a complete none; an unusable account with no match elsewhere (unknown, not none); a provider whose listing fails (unknown); a match plus an unusable account. The devcloud gates pass through `ci-gate` from this worktree.
6. devcloud's version is bumped in the same change (`scripts/bump-version.sh --plugin devcloud`; `--since origin/main` checks it), and the nested `CLAUDE.md` beside the code says what the command is for.
