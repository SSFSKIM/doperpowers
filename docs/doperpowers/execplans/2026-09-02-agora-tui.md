# agora tui — a navigable organisation chart of a seat fleet, with Enter opening the seat's live conversation

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds. It is maintained in accordance with `skills/execplan/references/PLANS.md` at the repository root.

## Purpose / Big Picture

`agora` is the fleet CLI of this plugin (`skills/agora/scripts/agora`, a six-line bash launcher around `skills/agora/scripts/agora.py`). It keeps a registry of *seats*: named positions in a *group*, each with a role, each filled by at most one background Claude Code session, each outliving the process that fills it. Today an operator sees that fleet as text: `agora list` is a table and `agora view <group>` is an indented tree. To open a seat's conversation they have to read a short id off the table and type `agora attach <seat>` in another terminal.

After this change an operator runs `agora tui` in a terminal and sees the whole institution as boxes: every group is a rounded root box, every live seat is a square box to its right showing alias, role, a state glyph and the one-line "now" status the agent set, connected to its parent by drawn lines. Arrow keys move a heavy-bordered focus from box to box (up and down between siblings, right into children, left back to the parent). Pressing Enter on a seat opens that seat's conversation in a new tmux window with `claude attach`; the chart stays alive in its own window, so the operator hops between the map and any conversation with plain tmux keys. `s` types a message to the focused seat and delivers it over the seat's inbox socket; `b` shows the group's board posts; the bottom panel always describes the focused seat (state, current work, last reply). Dead seats — retired, failed, or lost by the harness — are folded into a "+N retired" note on their parent so the chart shows the living organisation, and `a` unfolds them. `agora tui <group>` narrows the chart to one group.

The same layout engine also runs non-interactively: `agora chart [group]` prints the box chart as plain text, so an agent (or a human in a non-tmux context) can read the organisation chart without curses, and the test suite can assert on the exact drawing.

To see it working after implementation: in a terminal on a machine with `tmux` and `claude` installed, run `skills/agora/scripts/agora tui`. The terminal becomes a tmux session named `agora` showing the chart. Move with the arrows, press Enter on a seat whose glyph is `●` (busy) or `○` (idle); a new tmux window named after the seat opens with its conversation. Press the tmux window-switch key (by default `Ctrl-b` then `0`) to return to the chart.

## Surprises & Discoveries

- Observation: the harness already ships a full-screen "agent view" — `claude agents` with no flags lists every session under "Needs input / Working / Completed" with Enter-to-attach and a prompt box for new sessions. A custom chart that re-lists sessions would duplicate it. The chart's whole value is the institutional structure the native view has no concept of: groups, roles, parent/child edges, the board, the seat that outlives its session.
  Evidence: tmux capture of `claude agents` on 2026-09-02 shows the three-section list and the footer `ctrl+s to switch views · ctrl+enter to start and open · esc to quit`.
- Observation: `claude attach <short>` on a STOPPED session wakes it ("Session is starting — showing its transcript until it appears"), continuing the same session id, and the harness row flips to `state: working, status: idle`. So Enter can attach to `busy`, `idle`, `blocked` and `stopped` seats alike; only `vacant` (no session) and `gone` (harness lost the row) need a different answer. A stopped session with no saved transcript fails with exit 1 and a "no saved transcript" message.
  Evidence: probe on `3b8a42d7` (a stopped seat) opened its transcript and `claude agents --json` afterwards listed pid 46524 for it; probe on `0c387569` (stopped before its first response) printed `Couldn't wake … no saved transcript` and exited 1.
- Observation: the attach client is a full session UI. `←` moves to the native agent view in the same process; `Esc` does not quit; `Ctrl+Z` is the documented detach. An in-place `exec` from a chart would therefore never return to the chart on `←`, which is why attach opens in its own tmux window.
- Observation: the harness records no tmux information anywhere agora can read. `claude agents --json --all` rows carry exactly `cwd, id, kind, name, pid, sessionId, startedAt, state, status`; the peer registry at `~/.claude/sessions/<pid>.json` carries no pane either. Any tmux integration is agora's own doing.
- Observation: real registries are wide and flat, and mostly dead. On this machine group `fleet` has 25 seats of which 23 are `gone` and none has a parent (board-pipeline workers are spawned by scripts, without `--parent`). A chart that showed everything would be a graveyard; the hide rule and the vertically-stacking layout below are answers to that data.
- Observation: `claude agents --json --all` takes about 1.2 s here, and `agora.py` caches its result (`_AGENTS`), the peer registry (`_PEERS`) and process start times (`_PSTART`) for the life of the process. A long-lived chart must refresh those caches on a timer or it will show the state at launch forever.

## Decision Log

- Decision: the chart is an institutional lens that complements the native agent view, not a fleet console that replaces it. It shows groups, seats, roles, edges, live state and the board; it delegates the inside of a session to `claude attach`; it does not list sessions outside the registry and has no "new session" prompt.
  Rationale: the native `claude agents` view already does the session list well; duplicating it costs code and confuses the operator about which surface is authoritative. Rejected: a full console (large, overlapping the harness) and shelving the TUI (the text `view` cannot show a wide fleet at a glance, and it has no path to a conversation).
  Date/Author: 2026-09-02, human partner via grill.
- Decision: left-to-right tree layout — roots on the left, children to the right, siblings stacked vertically, the whole chart scrolling vertically. Keys: `↑`/`↓` move between nodes in the same column, `→` enters the first child, `←` returns to the parent.
  Rationale: real groups have wide sibling fan-out and shallow depth; stacking siblings vertically needs only vertical scrolling, which terminals do naturally, and never needs the row-wrapping a top-down org chart would need for a level of twenty boxes. Rejected: top-down org chart (classic look, but wide levels overflow horizontally and wrapped levels have no clean connector drawing); boxed row list (dense and simple, but the visual hierarchy the partner asked for is weak).
  Date/Author: 2026-09-02, human partner via grill.
- Decision: the interactive chart always runs inside tmux. Started outside tmux, `agora tui` re-executes itself inside `tmux new-session -A -s agora`. Enter opens `claude attach <short>` in a new tmux window named after the seat; if that seat's window is still open, Enter switches to it instead of opening a second one.
  Rationale: the attach client's `←` key leads to the native agent view and only `Ctrl+Z` detaches, so an in-place `exec` could never return the operator to the chart reliably; a separate window keeps the chart alive and makes "back to the map" an ordinary tmux window switch. Rejected: split pane beside the chart (halves the chart's width, which the left-to-right layout needs); in-place exec without tmux (no dependency, but the return path is broken as described).
  Date/Author: 2026-09-02, human partner via grill.
- Decision: v1 actions are attach (Enter), send (`s`), a detail panel for the focused seat, and a board panel (`b`) with a read-only post overlay. Lifecycle verbs (wake/retire/fill) and posting to the board are not in v1.
  Rationale: send is the communication paneling the initiative is for; the detail and board panels are reads. Lifecycle verbs mutate the fleet and need confirmation and task-text input, which is a second slice. Rejected for v1: wake/retire/fill.
  Date/Author: 2026-09-02, human partner via grill.
- Decision: dead seats are hidden by default and folded into a "+N retired" note on their parent (or into the header count for roots); `a` toggles showing everything. A seat is dead when its recorded `status` is `retired`, `failed` or `error`, or when its live state is `gone`. A dead seat with a living descendant stays visible (dimmed) so the tree keeps its shape. `stopped` seats are shown, because Enter can wake them.
  Rationale: 23 of 25 seats in the real `fleet` group are dead; a chart that shows them all is unreadable and says nothing about the living organisation. Rejected: show everything dimmed (history always visible, chart unusably long).
  Date/Author: 2026-09-02, human partner via grill.
- Decision: verbs are `agora tui [group]` (interactive) and `agora chart [group]` (static text). Without a group both show the whole fleet with one rounded box per group as the root of that group's seats.
  Rationale: `tui` is the CLI convention (k9s, lazygit, gh dash) that says "interactive" on sight; a separate static verb gives agents and tests the same drawing without a terminal. The fleet-first default shows the whole institution at a glance and reuses the same layout engine with the group as a virtual root; a group picker would be an extra step for a poorer view. Rejected: `agora panel` (memorable, but ambiguous about interactivity); `agora view --interactive` (a flag that changes the verb's whole nature); a group-picker start screen.
  Date/Author: 2026-09-02, human partner via grill.
- Decision: stdlib `curses` for the terminal layer, in a module that imports `agora.py` for data. No third-party package.
  Rationale: `agora.py` is stdlib-only by an earlier decision, and adding `textual` or a Node stack would make a skill that installs with a `git clone` require a package install. curses is present in every CPython on macOS and Linux (verified: Python 3.12.3, curses 2.2 on this machine). The painter writes to a small screen abstraction so the same code renders to a text grid for tests.
  Date/Author: 2026-09-02, author.
- Decision: layout, painting and key handling are pure functions over an explicit state; only the outermost loop touches curses, tmux or subprocesses. `agora tui --headless --keys …` drives the same code with a scripted key list and prints the final grid and the actions taken.
  Rationale: curses cannot run without a TTY, so an untestable TUI is the default outcome; separating the state machine from the terminal makes every behaviour assertable from the existing bash suite. Rejected: driving a real curses session in tmux from the tests (slow, flaky, needs tmux on CI).
  Date/Author: 2026-09-02, author.
- Decision: the chart calls `agora.py` functions in-process for reads (seats, live state, replies, board) and shells out to the `agora` launcher for `send`.
  Rationale: reads are plain functions; `send` is a verb that calls `die()` (which exits the process) on refusal and carries identity rules, so running it as a subprocess keeps its exit code and message intact and keeps the chart process alive.
  Date/Author: 2026-09-02, author.

## Context and Orientation

This repository is `doperpowers`, a plugin of skills for coding agents. The skill that matters here is `skills/agora`: `skills/agora/SKILL.md` documents the fleet model and the CLI; `skills/agora/scripts/agora` is a bash launcher that runs `skills/agora/scripts/agora.py` with the same arguments; `skills/agora/scripts/agora.py` (about 2,800 lines, standard library only) implements every verb; `skills/agora/references/spawn-preamble.md` is the text prepended to every spawned seat's task. Tests live in `tests/agora/run-agora-tests.sh` (about 1,350 lines, bash, run from the repository root as `tests/agora/run-agora-tests.sh`; it prints one `ok`/`FAIL` line per assertion and ends with a count, currently 406 passing).

The *registry* is a directory (default `~/.claude/agora`, overridable with the `AGORA_HOME` environment variable) holding one `<uuid>.json` record per seat, plus `<uuid>.reply.txt` (the seat's last reply text), plus `groups/<group>/board.jsonl` (the group's board, one JSON post per line with `id`, `ts`, `from`, `title`, `text`). A *seat record* has these fields after `agora.load_seat()` normalises it: `seat_id` (the file name), `alias` (the seat's name; letters, digits, dot, underscore, dash, at most 64 characters), `group`, `parent` (another alias in the same group, or empty), `role`, `brief`, `now` (a one-line status the agent set with `agora mark --now`), `status` (the recorded turn state: `working`, `blocked`, `idle`, `error`, `retired`, `done`, `awaiting-human`, `failed`, or `?`), `current` (the session id filling the seat, or empty), `short` (the harness's eight-character id for that session), `cwd`, `addr`, `updated`, and more. `agora.public_seat(s)` drops the task body and secret-shaped fields and is what every model-facing surface prints.

*Live state* is what the harness says right now, computed by `agora.live_state(seat)`: `busy`, `idle`, `blocked` (the session is waiting on a permission or question), `stopped` (the session exists but its process is not running), `gone` (the seat records a session the harness no longer knows), `vacant` (no session at all), or `unknown` (the harness could not be asked). It is derived from `claude agents --json --all` (cached in `agora._AGENTS`, refreshed by `agora.agents_refresh()`) and from the harness *peer registry* `~/.claude/sessions/<pid>.json` (cached in `agora._PEERS`, never refreshed today) plus a socket connect to the session's inbox socket. `agora.FILLED` is the tuple `("busy", "idle", "blocked")`.

`agora.harness_row(seat)` returns the harness row for the seat's current session (a dict with `id`, the short id `claude attach` takes). `agora.seats(group=None)` returns every seat record, or one group's. `agora.read_board(group)` returns the list of posts. `agora.reply_text(seat_id)` returns the last reply text. `agora.now_or_reply(seat)` returns `now` or the first 46 characters of the reply. `agora.children_of(group_seats, alias)` and `agora.tree(group)` implement the parent/child walk the text `view` uses; `cmd_view` (around line 2290) and `cmd_topology` (around line 2316) are the current text and JSON views; `cmd_attach` (around line 2349) execs `claude attach <short>` when the seat is filled. Verbs are registered in `build_parser()` (around line 2545) with `sub.add_parser(name, add_help=False)` and `set_defaults(fn=cmd_x)`; `main()` runs `migrate()` then `a.fn(a)`. `usage()` prints the help text and must mention new verbs.

The *harness* is Claude Code. `claude --bg` starts a background session and prints a banner with a short id; `claude agents --json --all` lists sessions; `claude attach <short>` opens a session in the current terminal (it wakes a stopped one; inside the client `←` goes to the harness's own agent view and `Ctrl+Z` detaches). A *live* session listens on a unix socket at `/tmp/cc-socks/<pid>.sock`; `agora send <seat> "text"` writes a message frame to it and the session receives it as a peer message (an idle session starts a turn).

*tmux* is the terminal multiplexer (3.7b here at `/opt/homebrew/bin/tmux`). The environment variable `TMUX` is set inside a tmux client. The commands used: `tmux new-session -A -s <name> <command…>` (create or attach), `tmux new-window -P -F '#{window_id}' -n <name> -- <command…>` (open a window running a command, print its id like `@7`), `tmux list-windows -F '#{window_id}'`, `tmux select-window -t <id>`.

*curses* is Python's standard terminal library. Facts a novice needs: call `locale.setlocale(locale.LC_ALL, "")` before `curses.wrapper` or non-ASCII box glyphs print as garbage; `curses.use_default_colors()` keeps the terminal's background; `stdscr.timeout(250)` makes `getch()` return `-1` after 250 ms so the loop can service a refresh queue; writing to the bottom-right cell raises `curses.error` and must be caught; `curses.KEY_RESIZE` arrives when the terminal is resized; `curses.KEY_UP/DOWN/LEFT/RIGHT`, `10`/`13` for Enter, `27` for Escape, `9` for Tab. East-Asian wide characters occupy two cells; `unicodedata.east_asian_width(ch) in ("W", "F")` detects them.

The test suite puts a stub `claude` first on `PATH`; its `agents --json` prints rows from a state directory the tests fill, so any live state can be fabricated (read the suite's stub section near the top, "environment: isolated HOME, registry, PATH-shadowed claude stub", before writing tests). It also runs a tiny unix-socket server standing in for a live session's inbox, so a real `agora send` can be asserted end to end.

## Plan of Work

### M1 — the chart engine and `agora chart`

Create `skills/agora/scripts/agora_chart.py`. It begins with `sys.path.insert(0, os.path.dirname(os.path.realpath(__file__)))` and `import agora`.

The *snapshot* is the data the chart draws. `snapshot(group=None, show_all=False)` returns a list of root *nodes*. A node is a dict: `kind` (`"group"` or `"seat"`), `id` (`"<group>"` for a group node, `"<group>/<alias>"` for a seat), `label` (group name or alias), `role`, `live` (the live state, `""` for a group), `status`, `now` (from `agora.now_or_reply`), `dead` (bool), `children` (list of nodes, sorted by label), `hidden` (count of dead direct children folded away), and `seat` (the `public_seat` dict, absent for groups). For each group it reads `agora.seats(group)`, computes `live_state` once per seat, builds the parent tree exactly as `agora.tree` does (a seat whose parent is unknown is a root; a seat whose parent is itself or forms a cycle is a root — guard with a visited set), and applies the hide rule: a seat is *dead* when `status in ("retired", "failed", "error")` or `live == "gone"`; when `show_all` is false a dead seat with no visible descendant is dropped and counted in its parent's `hidden` (roots count into the group node's `hidden`; in single-group mode into a returned `hidden_roots` value — make `snapshot` return `(roots, hidden_roots)`). In fleet mode (no group) every group becomes a group node whose children are that group's roots; a group with no visible seats is dropped unless `show_all` and counted in a `hidden_groups` total that the header shows. Groups are the union of `agora.seats()` groups and `groups/*` directories, as `cmd_groups` computes.

The *layout* is pure: `layout(roots, box_lines=3, gap=4, min_w=16, max_w=30)` returns a dict with `boxes` (list of `{node, x, y, w, h}`), `edges` (list of drawable segments), `width`, `height`. Box height is `box_lines + 2` (borders). Column width is uniform per depth: the maximum display width of any content line of any node at that depth plus 4 (two border cells, two padding cells), clamped to `[min_w, max_w]`. Column `d` starts at `x = sum(width of columns 0..d-1) + d * gap`. Vertical placement is post-order: a leaf takes the next free `y` (a cursor that advances by `h + 1`); a parent is centred on the span of its children (`y = (first_child.y + last_child.y) // 2`), which never overlaps a sibling because children spans are disjoint and ordered. Edges are computed from the boxes: for a parent with children, a horizontal stub from the parent's right edge at its middle row, a vertical bus at `x = parent.right + 2` running from the first child's middle row to the last child's middle row, and a two-cell stub into each child's left edge; a single child gets one straight `────`. Junction glyphs: `┬` where the bus starts if the parent's row is above it, `┴` if below, `┼` where the parent's stub meets the bus mid-span, `├` at each intermediate child, `┌`/`└` at the ends when the parent's row is not there.

The *painter* is pure over a `Screen`: `class Screen` with `w`, `h`, `put(y, x, text, attr=0)` (clips to the screen, handles wide characters), and `class GridScreen(Screen)` whose `text()` returns the rows joined by newlines with trailing spaces stripped. `paint_chart(screen, lay, focus_id=None, ox=0, oy=0, styles=None)` draws boxes and edges shifted by the viewport offsets. A seat box's three content lines are: line 1 `alias` left and `ROLE` (upper-cased role, empty if none) right; line 2 the state glyph and live word (`● busy`, `○ idle`, `◐ blocked`, `■ stopped`, `◌ vacant`, `✕ gone`, `? unknown`); line 3 `now` truncated to fit with `…`, or `+N retired` when the node hides children and has no `now`, or empty. Group boxes use rounded corners `╭╮╰╯`, show the group name on line 1, `N seats · M live` on line 2 and `+N retired` on line 3 when applicable. The focused box uses heavy borders `┏━┓┃┗━┛`. Dead-but-shown nodes render with the dim style. Text width and truncation go through `dwidth(s)` and `fit(s, n)` helpers that count wide characters as two cells; every content line is padded to exactly the column's inner width so boxes stay aligned when `now` contains Korean.

Add the verb: in `agora.py` `build_parser()`, `ch = sub.add_parser("chart", add_help=False)` with a positional optional `group`, `--all`, `--width N` (default: terminal width if stdout is a TTY, else 120), and `set_defaults(fn=cmd_chart)`. `cmd_chart` validates the group as `cmd_view` does (bad name → exit 2, unknown group → exit 4), imports `agora_chart` lazily, builds the snapshot and layout, paints onto a `GridScreen(width, lay["height"])` and prints `screen.text()`, then one summary line: `N seats · M live · K hidden (agora chart --all)` (and `G groups` in fleet mode). Add the verb to `usage()`.

Add `agora.refresh_caches()` to `agora.py`: sets `_AGENTS_LOADED = False`, `_PEERS = None`, and clears `_PSTART`; returns `agents_json()`. `agents_refresh()` may simply call it.

Tests (append a section `# ---- N) chart` to `tests/agora/run-agora-tests.sh`, before the final count): build a group `org` with `agora seat add` for `lead` (role LEAD), `scout` (parent lead, role RES), `scribe` (parent lead, role DOC), `intern` (parent scribe), `qa` (parent lead), fabricate harness rows so `lead` is busy, `scout` idle, `scribe` busy, `qa` blocked, `intern` vacant (no session), plus `old-worker` (parent lead) marked `retired`. Assert: `agora chart org --width 120` contains `lead` and `LEAD` on the same line, contains `● busy`, `○ idle`, `◐ blocked`, `◌ vacant`, does not contain `old-worker`, contains `+1 retired` in the `lead` box, contains a `─┬──` or `┬` junction; `agora chart org --all` contains `old-worker`; `agora chart` (fleet) contains a group box line with `org` and `5 seats`; a `now` value with Korean text (`agora mark org/scout --now "스펙 읽는 중 어쩌구저쩌구 매우 긴 문장입니다"`) renders every line of that box at the same display width (assert with a small python check over the output); `agora chart nope` exits 4; `agora chart bad/name` exits 2.

### M2 — the interactive application

Create `skills/agora/scripts/agora_tui.py`, importing `agora` and `agora_chart` the same way.

State is a plain dict (`State`): `group` (or `None`), `show_all`, `roots`, `lay`, `focus` (a node id), `ox`, `oy` (chart viewport offsets), `panel` (`"detail"` or `"board"`), `panel_focus` (bool: board list has the keyboard), `board_cursor`, `overlay` (`None`, `"help"`, or `("post", post)`), `overlay_scroll`, `input` (`None` or the text being typed for send), `flash` (a footer message and the time it was set), `refreshed_at`, `refreshing`, `hidden_roots`, `hidden_groups`, `attached` (dict alias → tmux window id), `actions` (list of strings, for headless output).

`handle_key(state, key, actions) -> None` is the whole keymap. `key` is a string token: `up down left right enter esc tab pgup pgdn home end resize` or a single character. Behaviour: with an overlay open, `esc`/`q`/`?` closes it and `up`/`down`/`pgup`/`pgdn` scroll it. In input mode, printable characters append, `backspace` deletes, `esc` cancels, `enter` submits (calls `actions.send(node, text)`). With the board list focused, `up`/`down` move `board_cursor`, `enter` opens the `("post", post)` overlay, `tab` returns focus to the chart. Otherwise, on the chart: `up`/`down` (also `k`/`j`) move to the nearest box in the same column with a smaller/greater `y`; `right` (`l`) moves to the first (topmost) visible child; `left` (`h`) to the parent; `home`/`end` to the first/last root; `enter` on a seat calls `actions.attach(node)`, on a group toggles that group's collapse (a collapsed group node shows `▸ N seats` and hides its children; keep a `collapsed` set in state); `s` on a seat starts input mode when `live in FILLED` and otherwise flashes `"<alias> is <live> — Enter attaches (wakes) a stopped seat; a vacant seat needs agora fill"`; `a` toggles `show_all` and rebuilds; `b` toggles the panel between detail and board; `tab` moves keyboard focus to the board list when the board panel is shown; `r` requests a refresh; `?` opens help; `q` quits. After every movement, `ensure_visible(state)` adjusts `ox`/`oy` (using the chart region size kept in state) so the focused box is fully inside the chart region.

Rebuild after data change: `rebuild(state)` recomputes `roots`, `lay` and keeps `focus` if its id still exists, else moves it to the first root. Sizes: header 1 row, footer 1 row, panel 7 rows (6 content + a separator), the chart gets the rest; when the terminal is under 16 rows the panel collapses to 0.

`paint(state, screen)` draws: the header (`agora · fleet` or `agora · <group>`, seat and live counts, `K hidden · a` when hidden > 0, and either `refreshing…` or `updated HH:MM:SS` right-aligned); the chart via `agora_chart.paint_chart` into the middle region; the panel — detail mode shows `group/alias · ROLE · seat <8 chars> · session <8 chars>`, `live · status`, `now: …`, `brief: …`, `cwd: …`, and the last reply's first two lines from `agora.reply_text`; board mode lists the last posts newest first as `#id  ts  from  title` with the cursor row highlighted, or `(no posts)`; the footer with key hints (`↑↓←→ move · enter attach · s send · b board · a all · r refresh · ? help · q quit`) replaced by the input line `send → group/alias ▏text` in input mode, or by the flash message for 5 seconds after it was set. Overlays paint a centred bordered box over everything: help lists the keys; a post shows its header and text wrapped to the box width, scrolled by `overlay_scroll`.

The `Actions` object separates decisions from effects. `class RealActions` does tmux and subprocesses (M3). `class HeadlessActions` appends `"attach <alias> <short>"` (and the tmux command it would run) or `"send <alias> <text> → rc=<n> <first output line>"` to `state["actions"]`; in headless mode `send` still runs the real `agora send` subprocess so the suite's socket server can assert delivery.

Two loops. `run_headless(args)`: builds state at `--width`/`--height` (defaults 120×40), takes one snapshot, applies the `--keys` list (comma-separated tokens; a token `text:hello` types each character), paints to a `GridScreen` and prints its text, then a line `--- focus: <id>` and `--- actions:` followed by one recorded action per line. `run_curses(args)`: `locale.setlocale`; `curses.wrapper(main_loop)`; inside, `curses.curs_set(0)`, `use_default_colors`, colour pairs for busy (green), idle (cyan), blocked (yellow), stopped (white), vacant/gone (dim), unknown (magenta), focus (bold), group (blue); `stdscr.timeout(250)`; a `threading.Thread(daemon=True)` that every `AGORA_TUI_REFRESH` seconds (default 3) calls `agora.refresh_caches()`, builds a new snapshot and puts it on a `queue.Queue`; the main loop drains the queue (rebuilding state and setting `refreshed_at`), translates `getch()` codes to key tokens (`KEY_RESIZE` → `resize`, which re-reads `getmaxyx`), calls `handle_key`, repaints through a `CursesScreen(Screen)` whose `put` calls `stdscr.addstr` inside `try/except curses.error`, and exits on `q`.

The verb: `tu = sub.add_parser("tui", add_help=False)` with optional positional `group`, `--all`, `--headless`, `--keys`, `--width`, `--height`, `--no-tmux`; `cmd_tui` validates the group like `cmd_view`, then: `--headless` → `run_headless`; else if `not sys.stdin.isatty() or not sys.stdout.isatty()` → `die("agora tui needs a terminal — use: agora chart [group]", EXIT_USAGE)`; else the tmux wrap check (M3) and `run_curses`.
