# agora — a CLI communication surface for groups of coding agents

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds. It is maintained in accordance with the ExecPlan contract vendored at `skills/execplan/references/PLANS.md` in this repository (doperpowers).

## Purpose / Big Picture

Claude Code sessions on one machine can already message each other point-to-point (the native `SendMessage` tool), but there is no way to scope a *working group* of agents, no record of who spawned whom, no durable conversation a human can inspect, and no way for a shell command — a human at a terminal, a dispatch script, a cron job — to send a message at all. When an orchestrator spawns three worker daemons today, the humans and agents involved have no shared picture of that little organization.

After this change, any agent or human can do the following, all through one executable:

    agora join demo architect --desc "designs the feature"
    agora send demo --from architect --to impl-1 "the plan is ready, start on M1"
    agora view demo          # human: ASCII tree of the group's spawn topology
    agora topology demo      # agents: the same picture as JSON
    agora log demo           # human: the whole conversation, rendered

Receiving is push, not poll: each member arms one persistent Monitor (a Claude Code tool that streams a command's stdout lines into the session as events) running `agora listen <group> <alias>`. A message lands in the member's inbox file, the tail emits it, and the harness wakes the receiving session. Messages to a member whose process is gone simply queue; the member drains its backlog on its next wake, and the human can see the unread count in `agora view`.

The system deliberately owns only the *group layer*: groups, topology, the durable log, the CLI surface, and the graph views. Point-to-point delivery to live sessions is a commodity the harness already provides; agora's file transport exists because shell processes have no other way in, and because files are the only substrate every participant (agent, human, script) shares.

## Surprises & Discoveries

- Observation: (from design research, 2026-08-26) Native cross-session `SendMessage` wakes an idle session immediately — "When the receiving session is idle, Claude Code starts a new turn with the message" (official cross-session-messaging docs). This retired an earlier assumption that daemons must be resumed by forking.
  Evidence: docs page `code.claude.com/docs/en/cross-session-messaging`, Message delivery section.
- Observation: A `claude --bg` session's OS process survives its turn ending, but the supervisor stops it after roughly one hour idle-and-unattached (pinned sessions exempt). The session stays revivable — attach/peek/reply restarts the process from saved state. Consequence: a dormant member's Monitor is dead, so agora messages to it queue in its inbox until its next wake. This is accepted behavior (Decision Log).
  Evidence: docs page `code.claude.com/docs/en/agent-view`, Background Session Lifecycle section.
- Observation: There is no native shell-level way to inject a message into a session (documented absence — no `claude agents send`). This is the fact that forces agora's file transport: CLI senders have nothing else to ride.
  Evidence: docs `cli-reference` / `headless` pages list only `-r`/`-c`/`-p` (which start turns via resume), nothing injection-shaped.
(M0's outcome will be recorded here once the smoke test actually runs.)

## Decision Log

Decisions from the brainstorming grill (2026-08-26, human partner + Claude), each with the losing alternative:

- Decision: File-based transport — group JSONL log as durable record, per-recipient inbox files for delivery; Monitor tail as the receive surface. Native SendMessage remains a sender-side accelerator only, never the record.
  Rationale: no shell-level injection exists, so CLI sends must write files; per-recipient fan-out keeps each member's Monitor event volume proportional to what is addressed to it (chatty monitors get auto-stopped by the harness). Rejected: riding native SendMessage as the transport (unreachable from shell; log would drift from reality via dual-write).
- Decision: Targets are always explicit; `send` with no `--to` is an error.
  Rationale: the human partner's model is one-to-one messaging with occasional multi-target batches, not broadcast; topology is *information* ("an advanced ListAgents"), not a router. Rejected: default-broadcast to graph neighbors, whole-group broadcast.
- Decision: Soft edges. The topology records parent→child spawn lineage; sending to a non-neighbor works but requires `--off-edge` and the record is marked, visible in log and views. `human` is always a legal target. Rejected: hard enforcement (fails the repo's Golden Rule — no enforcement beyond necessity; the rare legitimate sibling exchange would need ceremony), and pure-viz edges (loses the N²-chatter friction entirely).
- Decision: The human is an omniscient operator, not a node. Sees everything, sends to anyone (edge rules don't apply), renders as `from="human"`. Rejected: human-as-root-node (forces artificial edges and routing rules onto a participant nobody spawned).
- Decision: Cheap named groups auto-created on first join, living under `~/.claude/agora/groups/<name>/`. Machine-global because members span repos and worktrees. Rejected: orchestrator-owned per-run groups (ceremony), one-per-project standing groups (log spans unrelated runs).
- Decision: Alias is the address; the current session id is refreshable metadata. For daemons the alias is the daemon name. Rationale: aliases are what humans type and what survives session churn. (Historical note: an earlier repo doctrine treated session ids as unstable because daemon resumes forked new sessions; that fork pattern is legacy — native SendMessage wakes idle sessions in place — but alias-as-address is simply better UX regardless.)
- Decision: Dormant members queue-and-surface. No force-wake tier in v1; `view`/`list` show unread counts so a human can nudge. Rejected: CLI force-wake via `claude -r` (needs an unproven spike on session-id stability), sender-side native ping as a *requirement* (excludes human/script senders; it remains an optional convention).
- Decision: Spawn integration patches `skills/orchestrating-daemons/scripts/daemon-spawn.sh`, gated on new env vars `AGORA_GROUP` / `AGORA_PARENT`, mirroring the script's existing env-injected gateway dimension (`DAEMON_CLAUDE_SETTINGS`). Rationale: code exploration showed `daemon-spawn.sh` is the live universal spawn path (both `execute-dispatch.sh` and `review-dispatch.sh` ride it); only the *resume* side is legacy. Rejected: a separate agora-owned spawn wrapper (splits the spawn path), prompt-only self-join (topology drifts when agents forget).
- Decision: Delivery renders as an XML envelope (`<agora-message …>…</agora-message>`), storage stays JSONL.
  Rationale: mirrors the harness's own `<cross-session-message from="…">` convention so the receiving model reads provenance-framed data, not stray log output; JSONL stays machine-parseable for views. Escaping via jq `@html` prevents message text from breaking the envelope.
- Decision: Name: `agora` (human partner's choice over partyline/switchboard/mesh).
- Decision: If M0 refutes Monitor wake for post-turn `--bg` sessions, the architecture stands anyway: receive degrades to backlog-drain-on-natural-wake, `view`/`list` surface unread counts, and the skill teaches senders the optional native-SendMessage ping for urgency. The go/no-go only shapes the delivery *posture*, not the build.
- Decision: `agora listen` emits each message BEFORE checkpointing its cursor, and uses `tail -F` (capital F). Rationale: emit-then-checkpoint gives at-least-once delivery — a listener dying between the two produces a visible duplicate on restart, whereas checkpoint-then-emit could silently drop a message from the event stream; duplicates are the acceptable failure. `-F` follows the file *name*, so an atomic replace or rotation of the inbox cannot silently detach the tail the way plain `-f` (which follows the descriptor) would.

Follow-on recorded, out of v1 scope: `skills/issue-tracker/scripts/board-answer.sh:296` is the last production consumer of the legacy resume-fork (`daemon-resume.sh`). Once agora is proven, the answer relay can deliver through agora instead (inbox append → Monitor wake → same session continues), retiring the fork machinery. Do not attempt it in this plan.

## Context and Orientation

This repository, `doperpowers`, is a Claude Code *plugin*: a collection of skills (instruction documents plus helper shell scripts) that load into coding-agent sessions. There is no application build; the product is the contents of `skills/`. Tests are shell scripts under `tests/`, run directly. Relevant existing pieces:

- `skills/orchestrating-daemons/scripts/daemon-spawn.sh` — spawns a durable background Claude session (a "daemon") via `claude --bg`, records it in a registry at `~/.claude/orchestrating-daemons/`, and prints a banner containing the new session's uuid. Its interface: `daemon-spawn.sh [--no-wait] <name> <task> [cwd] [worktree] [model]`, plus env-injected dimensions (`DAEMON_CLAUDE_SETTINGS`, `DAEMON_CLAUDE_EFFORT`). Both production dispatchers (`skills/executing/scripts/execute-dispatch.sh`, `skills/qa-loops/scripts/review-dispatch.sh`) call it.
- The Claude Code **Monitor tool**: an in-session tool that runs a shell command in the background and turns each stdout line into a conversation event; with `persistent: true` it runs for the session's lifetime. This is agora's receive surface.
- Native **SendMessage/ListAgents** tools: point-to-point cross-session messaging on one machine, flat discovery. Agora layers groups/topology/log/CLI on top; it does not replace them.
- Terms: a **group** is a named set of participating sessions. A **node** is one member, addressed by its **alias**. An **edge** is the recorded parent→child spawn relationship. **Dormant** means a member whose OS process the harness supervisor has stopped (happens after ~1h idle-and-unattached); its messages queue.

Everything agora adds lives in three places: a new skill directory `skills/agora/` (the CLI executable, a spawn-preamble template, and `SKILL.md`), a new test directory `tests/agora/`, and one env-gated patch inside `daemon-spawn.sh`.

Runtime state (not in the repo) lives under `$AGORA_HOME`, default `~/.claude/agora`:

    ~/.claude/agora/groups/<group>/
      log.jsonl            one JSON object per line: every message in the group
      inbox/<alias>.jsonl  per-recipient copies of messages addressed to <alias>
      cursor/<alias>       integer: how many inbox lines were already delivered
      nodes/<alias>.json   membership record for <alias>
      locks/send.lock      flock target serializing appends

Group names and aliases match `^[A-Za-z0-9._-]{1,64}$`. The alias `human` is reserved for the operator and can never be joined.

A message record (log and inbox lines are identical):

    {"ts":"2026-08-27T04:12:33Z","from":"architect","to":["impl-1"],"text":"plan ready","off_edge":false}

A node record:

    {"alias":"impl-1","parent":"architect","session":"<uuid or empty>","cwd":"/abs/path","branch":"worktree-agora","desc":"one line","joined":"<ISO>","updated":"<ISO>"}

## Plan of Work

All new shell code is bash with `set -euo pipefail`, shellcheck-clean (`scripts/lint-shell.sh` must pass; if it reports "No shell files found" run `shellcheck` directly on the new files — see M1). `jq` is a hard dependency (already assumed elsewhere in this repo).

Create `skills/agora/scripts/agora` — ONE executable bash file with subcommand dispatch (`case "$1" in join|leave|send|listen|log|list|view|topology|groups)`). Shared helpers at the top: `_home` (resolve `$AGORA_HOME`), `_gdir <group>` (path + existence check), `_valid_name`, `_now` (UTC ISO-8601), `_append <file> <line>` (flock + printf '%s\n' >> under `locks/send.lock`), `_unread <group> <alias>` (inbox line count minus cursor).

Subcommand behavior, precisely:

- `join <group> <alias> [--parent P] [--desc D] [--session S]` — validate names (reject `human`); `mkdir -p` the group skeleton; write `nodes/<alias>.json` with cwd=`$PWD`, branch=`git -C "$PWD" branch --show-current` (empty outside a repo), preserving `joined` if the node file already exists (idempotent re-join refreshes everything else and `updated`). `touch inbox/<alias>.jsonl`. Print one line: `joined <group> as <alias> (parent: P|none)` plus, on its own indented line, the exact Monitor arm instruction (see M2) so a novice agent can copy it.
- `leave <group> <alias>` — remove the node file if present; keep inbox/cursor/log (history is never destroyed). Idempotent.
- `send <group> [--from F] [--to A,B,...] [--off-edge] [text...]` — `--from` defaults to `$AGORA_ALIAS`, then `human`. `--to` is required; comma-separated aliases; each must be `human` or an existing node. Text = remaining args joined with spaces; if none, read stdin (this is how long messages travel). Edge rule: when the sender is not `human`, a target is *in-edge* iff it is the sender's parent, one of its children (some node whose `parent` equals the sender), or `human`; any out-of-edge target requires `--off-edge`, otherwise exit 3 with a message naming the sender's actual neighbors. Build the record with `jq -cn` and append it to `log.jsonl` and each target's inbox (skip inbox for target `human`? No — write `inbox/human.jsonl` too, so the operator has a personal queue; `human` has no node file and that is fine). All appends run under one flock so records interleave whole.
- `listen <group> <alias>` — never exits. Touch the inbox; read cursor N (0 if absent); then `tail -n +$((N+1)) -F inbox/<alias>.jsonl` piped into a `while IFS= read -r line` loop that (1) renders the envelope to stdout, (2) increments N and rewrites `cursor/<alias>` atomically (tmp file + `mv`). Envelope, rendered with jq `@html` escaping on the text (and attribute values already charset-safe):

      <agora-message group="demo" from="architect" ts="2026-08-27T04:12:33Z">plan ready</agora-message>

  with ` off-edge="true"` inserted after `ts` when the record says so. One message = one line, so the Monitor turns it into one event.
- `log <group> [-n N] [-f]` — human rendering of `log.jsonl`: `[04:12:33] architect → impl-1: plan ready`, off-edge lines prefixed `⚡`. Default last 30 lines; `-f` follows.
- `list <group>` — one line per node: alias, parent, unread count, dormant-agnostic session id, desc. This is the "advanced ListAgents".
- `view <group>` — ASCII forest from parent pointers: roots (empty/unknown parent) at column 0, children indented with box-drawing (`├──`, `└──`), each line `alias — desc [3 unread]`. Nodes whose parent is named but missing render under a `(dangling)` header. After the tree, scan the last 200 log lines for `off_edge:true` and print `⚡ a ⇢ b (n)` pairs. Pure bash+jq; no external graph libs.
- `topology <group>` — JSON to stdout: `{"group":G,"nodes":[<node records + "unread":n>],"edges":[{"from":parent,"to":alias}...],"off_edge_activity":[{"from":F,"to":T,"count":N}...]}` (edges derived from parent fields; activity from the same log scan as `view`).
- `groups` — each group name with member count and mtime of `log.jsonl`.

Patch `skills/orchestrating-daemons/scripts/daemon-spawn.sh` (M4): read `AGORA_GROUP`/`AGORA_PARENT` next to the gateway env vars. When `AGORA_GROUP` is non-empty: (1) prepend to the task a preamble rendered from `skills/agora/references/spawn-preamble.md` (placeholders `{{GROUP}}`, `{{ALIAS}}`, `{{PARENT}}`, `{{AGORA_CLI}}`); (2) prefix the `claude` invocation env with `AGORA_ALIAS="$name" AGORA_GROUP="$AGORA_GROUP"` so the child's shell defaults work; (3) after the uuid materializes (both the `--no-wait` and waiting paths), run `agora join "$AGORA_GROUP" "$name" --parent "${AGORA_PARENT:-}" --session "$uuid"` from the daemon's run cwd, and add `agora_group` to the registry meta via the existing `meta_extra` array. The agora CLI path resolves relative to the daemon script: `$DIR/../../agora/scripts/agora`. A join failure must warn, not kill the spawn (the daemon matters more than its directory entry).

The preamble template stays short and principle-shaped (this repo's authoring rule): you are node `{{ALIAS}}` in agora group `{{GROUP}}` (parent: `{{PARENT}}`); arm your receive surface now with the Monitor tool (persistent, command `{{AGORA_CLI}} listen {{GROUP}} {{ALIAS}}`); discover peers with `{{AGORA_CLI}} topology {{GROUP}}`; message with `{{AGORA_CLI}} send {{GROUP}} --to <alias> "..."`; when you spawn children through daemon-spawn.sh, export `AGORA_GROUP={{GROUP}} AGORA_PARENT={{ALIAS}}`.

Write `skills/agora/SKILL.md` (M5): frontmatter `name: agora`, description triggering on operating/joining agent groups, viewing agent topology, inter-agent messaging via CLI. Body: the protocol for agents (join → arm listener → send explicit targets → `human` is always reachable for escalation), the operator commands for humans (`view`, `log`, `list`, `send` — operator sends need no flags beyond `--to`), the spawn-integration env vars, and the dormant-member semantics (queued messages drain on next wake; unread counts visible). No enforcement language beyond the one `--off-edge` gate.

Tests `tests/agora/run-agora-tests.sh` (grown across M1–M3): pure bash, no live Claude. Every test runs against `AGORA_HOME="$(mktemp -d)"`. Cover: join idempotency (joined preserved, updated refreshed); name validation (bad charset and `human` rejected); send edge rules (parent↔child ok; sibling without `--off-edge` exits 3 and names neighbors; with flag succeeds and record carries `off_edge:true`; `--from` defaulting from `AGORA_ALIAS`; human sender bypasses edges); fan-out (one send to two targets appends 1 log line + 2 inbox lines, identical records); stdin body; listen backlog+cursor (pre-seed 2 messages, run `timeout 3 agora listen ...`, assert two envelope lines and cursor==2; append a third during a second run, assert only it is emitted); envelope escaping (`<`, `&`, quotes in text arrive @html-escaped, envelope stays one line); topology JSON shape (jq asserts nodes/edges/unread); view smoke (tree glyphs + dangling section). The runner prints `ok <name>` per case and exits non-zero on first failure, matching the repo's plain-shell test style.

## Validation and Acceptance

Acceptance is behavior, verified from a terminal:

1. After `agora join g a` and `agora join g b --parent a`, `agora view g` prints a two-node tree with `b` under `a`, and `agora topology g | jq '.edges'` yields `[{"from":"a","to":"b"}]`.
2. `agora send g --from a --to b "hi"` appends identical records to `groups/g/log.jsonl` and `groups/g/inbox/b.jsonl`; `agora send g --from b --to b2 …` where `b2` is `b`'s sibling exits 3 and its stderr names `b`'s real neighbors; adding `--off-edge` makes it succeed and `agora log g` marks the line with `⚡`.
3. With two messages pre-seeded for `b`, `timeout 3 agora listen g b` prints exactly two `<agora-message …>` lines and leaves `cursor/b` containing `2`; running it again prints nothing new until a third send arrives.
4. `tests/agora/run-agora-tests.sh` exits 0 with an `ok` line per case; `scripts/lint-shell.sh` passes (or plain `shellcheck` on the new files reports nothing).
5. The M6 fleet demo: a human `agora send` to the architect daemon produces, within about a minute and with no manual resumes, architect→implementer and implementer→architect traffic in `agora log demo` and a final architect→human message — proving CLI send, Monitor wake, spawn auto-join, and topology all work together live.

## Idempotence and Recovery

Every command is safe to re-run: `join` refreshes, `leave` and `mkdir -p` are no-ops on repeat, sends only append, `listen` restarts from the cursor (a message re-emitted because the listener died between emit and checkpoint is a visible duplicate, never a silent loss). Test runs never touch real state (`AGORA_HOME` under `mktemp -d`). Live-demo groups are throwaway names (`demo`, `m4test`); `rm -rf ~/.claude/agora/groups/demo` is the whole cleanup, plus `daemon-retire.sh` for smoke/demo daemons. The `daemon-spawn.sh` patch is additive and env-gated: with `AGORA_GROUP` unset the script's behavior is byte-for-byte unchanged, so nothing in the board pipeline moves until a dispatcher opts in.
