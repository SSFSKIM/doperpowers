# sminos/

A fourth plugin in this marketplace, standalone (versioned on its own: `scripts/bump-version.sh --plugin sminos`; it declares no dependency, and nothing of doperpowers' is needed for it to run): the project family, its CLI and shell hooks, the bridge, the ask tool, the question sheet and the session's address; design `docs/doperpowers/specs/2026-10-19-sminos-plugin-design.md`.

Its place in the hook order is the owner's settings': `prependPlugins` in `~/.claude/settings.json` (a host's managed settings likewise) names `to-human@doperpowers`, `sminos@doperpowers` and `doperpowers@doperpowers`, which seats its hooks outside doperpowers' and every user-tier plugin's, devcloud's secrets guard and cua's among them; no dependency can, since the engine puts a dependent outside its dependency and pushes a plugin others depend on behind every one nobody depends on.

The plugin's own files below are named from `sminos/` (`docs/` paths are the repository's). Each part's detail sits beside its code: the CLI, the daemon and its uplink in `skills/sminos/scripts/CLAUDE.md`, the shell hooks in `hooks/CLAUDE.md`, the function hooks in `hooks/mods/CLAUDE.md`.

The CLI is `skills/sminos/scripts/sminos.py` (its launcher `sminos` beside it); `bin/sminos` runs it from the plugin's `bin/`, which the engine puts on the Bash tool's PATH in every session (interactive, `--bg`, `claude -p`, a subagent), so what a session is told (the guide, the skill, the spawn preamble) names it `sminos`; a peer frame's reply line keeps the absolute path, since its recipient may run without the plugin's bin/ (a session started before the plugin had one, an SDK session). It is reached on a machine at `<clone>/sminos/skills/sminos/scripts/sminos.py`, the path `daemon install` writes into the service; doperpowers' old path, `skills/sminos/scripts/sminos.py`, no longer exists, so a service installed before the move fails until `sminos daemon install` is rerun.

The project family: a committed `.smns` names a project, every session working under it (spawned seat, one the human opened, or one the MAWS app launched, which marks it with `SMNS_MEMBER` since its entrypoint is `sdk-ts`) is a member from its start, its project read from the directory it was launched in (a `cd` never moves it) unless it declares another with `sminos join <project>`; on a machine enrolled at a desk hub a repository no `.smns` claims is the hub project its remote derives (`origin`, else its only remote, normalized: one id from every clone, worktree and machine, nothing committed; design `docs/doperpowers/specs/2026-10-19-smns-remote-identity-design.md`), and a directory neither claims is in the machine's own project (`@<machine>`), so every session there is in a synced project; and what crosses sessions — `say` to peers (untagged is a record, `@alias` delivers, a stopped member woken in the background to take it, `@all` wakes every live member, a selector — `list`'s filters — every live session of its scope in any project, recorded in each project it reaches), a member's `<message>` to the human, joining, an in-charge line, spawning a sibling, retiring — is one event in the project's append-only log, one file per writer under `$SMINOS_HOME/projects/<id>/log/`.

The channel family (`sminos channel create|add|remove|show|env|lead`, `list --channel`): a declared channel is a log whose id is a UUID of version 8, which crosses projects and machines and holds threads placed in it by a statement in each thread's own project log, and is spoken in by naming it (`say --in <channel>`, `@<channel>/<alias>`), its messages owed to its members by thread; its detail is the channel paragraphs of `skills/sminos/scripts/CLAUDE.md` (code `skills/sminos/scripts/sminos_channels.py`; design `docs/doperpowers/specs/2026-11-21-sminos-channels-ch-design.md`).

The question sheet (the ask tool's second form, behind `SMINOS_QUESTION_SHEET`, off by default) is MAWS's composite `docs/doperpowers/specs/2026-11-23-question-sheet-design.md`, child C2, built from `docs/doperpowers/plans/2026-11-23-question-sheet-c2-sminos.md`; its mod is described in `hooks/mods/README.md` ("sheet"), its record and the `sminos sheet` verbs in `skills/sminos/scripts/CLAUDE.md`. `types/sheet/` is the set MAWS pins (schemas, examples, fixtures, with a manifest and digest): frozen, written by `tests/sheet-contract.gen.py` and never by the code it holds to account, and changed only by a ruling of the composite's writer and a new manifest `version`.

The Task Board (`sminos task`: what sessions ask the human to do in the world, one store a machine, `$SMINOS_HOME/tasks/`) is child B1 of `docs/doperpowers/specs/2026-11-27-task-board-design.md`, built from `docs/doperpowers/plans/2026-11-27-task-board-b1.md`; the store, its verbs, the door and the start line are described in `skills/sminos/scripts/CLAUDE.md`, its hook in `hooks/CLAUDE.md`, and `types/tasks/` is the set MAWS pins, written by `tests/tasks-contract.gen.py` and frozen as the sheet's is.

A second skill, `skills/manager/`, is the owner's read-only session manager (design `docs/doperpowers/specs/2026-10-31-session-manager-design.md`); its command, which imports the CLI's modules and adds no sminos verb, is described in `skills/manager/scripts/CLAUDE.md`.

The skill's body is what a member acts on; machine setup (the project and its mirror, the machine's place at the hub, the daemon, the policy) is its `references/setup.md`.

Design in `docs/doperpowers/specs/2026-10-13-smns-project-log-design.md`; the hub side in `docs/doperpowers/plans/2026-10-15-desk-dc4-uplink.md`, a child of the desk's composite design in MAWS, whose DX2 transport RL10 to the machine's endpoint superseded (board #153, `docs/doperpowers/specs/2026-11-07-sminos-phase1-removal-design.md`).

A check that a value is whole (an id, a name or a word from a frame, a record or a file name) is `fullmatch`, never `match` against `^…$`: Python's `$` also matches before a trailing newline, so `match` passes `"x\n"` (board #179). The mods' JavaScript `$`, with no `m` flag, does not.

Tests: `tests/run-sminos-tests.sh` (the `sminos` gate), `tests/mods/run.sh` (the `sminos-mods` gate).
