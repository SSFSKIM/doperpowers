# sminos/skills/sminos/scripts/ — the sminos CLI, the daemon and its uplink

A path here is named from `sminos/` when it is the plugin's own file; `docs/`, `sminos/…` and `to-human/…` paths are the repository's.

With a remote in `.smns` the log is a git working tree mirrored through it, and `sminos daemon` (one per machine; `daemon install` writes a launchd agent on macOS, a systemd user unit on Linux) syncs the mirror, delivers remote messages to local members, and publishes their state, so a project spans machines.

A project whose `.smns` names a desk hub instead (`project init --hub`; the file names the org alone, `"hub": {"org": …}`, each machine's enrollment the hub's URL, as doperpowers' own `.smns` does) syncs through the hub alone, never through git, on a machine cut over to its endpoint (below: enrolled by mawsd, and welcomed by it over RL10): `daemon run` supervises `daemon uplink`, a child process holding the endpoint's connection, which uploads the machine's own writers as drafts the endpoint signs, and imports each event the endpoint relays only once the endpoint has signed and verified it, and the machine writes under the name its endpoint gave it (`hub show` prints that identity, never a secret). Over the same connection the uplink serves the desk's session plane and its RPCs, the daemon being the execution boundary: presence from the engine's session records, each subscribed session's transcript and its bridge's stream joined in one order, the bridges' pending requests and their settlements, and the outcome of each delivery of a message from outside the machine; presence carries what each session's bridge can do (`capabilities`), the permission mode it last read (`mode`, DX4's ModeReading `{mode, at}`: its child's status's `permissionMode` and `permissionModeAt` as the mod last posted them, the bridge's own reading, so the body moves only when the session reports a mode, never as the probe asks again, and an idle session's switch reaches it within a probe, `BRIDGE_RECHECK`; absent until the bridge has read one) and the machine's `desk` (its sminos version, its RPCs), a `read` frame is answered on its subscription from the bridge (an `mcp` read with the servers the session's project disables added: `projects[<key>].disabledMcpServers`, the one key read of the engine's global config, the file and the key chosen as the engine chooses them — the legacy `.config.json` while it is nonempty, and a linked worktree's primary checkout), and a desk command's run and a side question's answer go up as `op`; an RPC (steer, interrupt, answer, decide, model, compact — its instructions passed to the bridge —, command, btw, stop-agent and tell — one subagent the session's tree holds as running, by its id, else the name of exactly one running agent (`unknown-agent`, `ambiguous-agent`), the id it resolved passed to the bridge, which acts on that agent alone —, spawn, media — an upload saved under the session's live working directory and handed to its bridge, which reads it in by a Read of its own —, and send — a person's message entered through the bridge's `deliver` under `{writer: rl10-send, seq}`, the seq reserved per session in `daemon/sends.json` as its frame arrives (above the mark the session's bridge kept, and above the file's `floor`, the highest seq of an entry a reserve dropped — hourly at most, a session gone with no bridge socket and nothing in flight — since the bridge's kept file is swept a day idle) and posted in that order, answered `{entered, uuid}`, `refused-delivery`, or `{submitted: true}` past 10 s (MAWS O9 §E) —; resume, retire and stop are offered and refused `unsupported`, below) runs only once the machine, project, and session it names, the at-most-once ledger (`daemon/rpcs.json`, keyed by the RPC's operation id — RL4's `opId`, which carries `opCreated` and is refused `expired` past `OP_HORIZON`, a day less an hour, so pruning never reopens one; else its nonce, as DX6 defined it, which keys an op kept before the cutover — `rpc-result` and `rpc-ack` keeping the nonce, an op's answer going up under its latest copy's, a copy that arrived while the op was in flight or claimed included; a tombstoned op refused `tombstoned`, and `query`/`tombstone` on the daemon's controller answering what became of an op, claim and tombstone one transition under one lock with the workers' `flight`; `sminos rpc-query [--created T] -- <opId>` prints the ledger file's view, without `flight` (`--` since a base64url id may start with `-`)), its age, the machine's policy, and, for an answer or a decision, the digest of the request still pending all hold (drawn from the input its raise carried, which for a permission past `RAISED_INPUT_MAX`, 256 KiB, is cut as the mod's resync cuts one and marked `truncated` — `sminos_requests.shown_input`, so no raise or complete set passes a lane's bound — or from the input whole; a scoped allow's rule, `decide.scope`, is resolved from that request's own suggestions, never from the browser: `session`, or the suggestion's own `localSettings`), and its result is sent again until the endpoint acknowledges it. The policy (`daemon/policy.json`, set by `sminos daemon policy [--read-only on|off] [--ceiling MODE|settings]`) can make the machine read-only — no RPC runs, nothing from outside is delivered — and caps a spawn's permission mode; a session whose record's controller is lane B is refused `lane-b` (reopening a MAWS lane B session is MAWS's), as is any op an observer's bridge refuses `lane-b`, a refusal its child kept and a restart reads back included. Such a project's remote keeps only the log's archive, which the one machine the hub designates for it writes on a schedule (`SMINOS_ARCHIVE_EVERY`, 15 minutes) from a clone at `projects/<id>/archive/`, never read back into the log.

Every enrolled machine follows every project of its org (the hub's `org` frame, kept at `daemon/org.json`), so `sminos list --org|--here|--project|--machine|--state [words]`, `find`, `projects` and `machines` show who works on what across the org, and `@short`, `@alias#short` and `@<project>/<alias>` reach any session there, recorded in both projects' logs (a bare `@alias` stays in the sender's project); design `docs/doperpowers/specs/2026-10-18-smns-org-directory-design.md`. Another machine's member reads its last published word, but `gone` once the directory retires its machine (`machine_retired`: its `machines` entry `retired: true`, as RL10's endpoint marks a machine no certificate stands for any more, or its machine project retired, as the hub retires a revoked machine's; by name, lower-cased), which `machines` shows `retired`. `machines` claims no presence, which the endpoint does not carry (the endpoint sends every machine `online: false`, and `seen` only as of its last restatement): this machine is `this machine`, another its newest event, the frame's `seen` or the logs' (`newest_events`); and the directory's age line says the endpoint restates it only when the org changes or the daemon reconnects.

A machine's enrollment is its MAWS `mawsd` endpoint's (`mawsd endpoint enroll|status`), and sminos reaches the hub only through it, over RL10 (O12 phase 2, M5; plan `docs/doperpowers/plans/2026-10-27-p5-o12-sminos-owners.md` in MAWS, the frames O10's Interfaces §D). `sminos_rl10.find` reads the endpoint's `rl10.json` (`$MAWS_USER_DATA/mawsd/endpoint/`, else O2's platform default; `SMINOS_RL10` for a test): a regular file of mode 0600 owned by this uid, protocol 1, a token of 64 hex characters and a socket, anything else no endpoint, said once in daemon.log. Before the cutover no uplink runs: `daemon run`'s supervisor only probes the endpoint (`sminos daemon probe`: dial, `hello` with the token, the welcome; backing off from 1 s to a minute, from 1 s again when rl10.json changes), and a refusal, a wrong token, silence, or a welcome whose identity is not whole (org, hub, name, ref and enrolled: an endpoint not enrolled yet, which `daemon status` says) leaves the machine as it is. A whole welcome cuts the machine over: `daemon/identity.json` (0600; org, hub, name, former, ref, enrolled, cutover, build; `former` this machine's own map of names to the sessions held under them, empty at the first welcome, a rename the endpoint made adding `sessions_under(old)` before the replace, and never shrinking) is the enrollment from then on, read alone by `enrollment`, `machine_identity`, `enrolled_at`, `hub show` and `project init --hub`; a stray `hub.json` enrolls nothing. The child (`daemon uplink`) speaks RL10 — `Link` over a `SocketTransport` (the reader, and one `SocketLane`: newline-delimited frames of at most 1 MiB, `part`s beyond; a frame written is taken, its continuation run on write, more than 16 MiB unsent ending the connection with `NotDelivered`; everything restated after each welcome and closed by `restated {}` once the whole restatement is queued — the member set, every hub project opened with its presence, pending set and unacknowledged results, the host events owed again (`Link.restated_due`) — since at `restated` the endpoint withdraws every session it left out; every session kind sent) — and while the endpoint is not running nothing runs (`daemon status`: `cut over; the endpoint is not running`; daemon.log at once and hourly). `hub enroll`, `check` and `leave` print where the enrollment is made and exit 1, reading no word given after them; removing identity.json undoes the cutover, in O14's order: the endpoint out first (rl10.json and its socket gone), then identity.json, after which no uplink runs until the next probe's welcome cuts the machine over again, at a new `cutover` time. The endpoint's `policy` (the welcome's, and each frame) is the machine's: written to `daemon/policy.json` with the endpoint's last word kept beside it (`endpoint`), so a `daemon policy` change made here goes up as `policy-set` and the file settles on the answer, and a welcome never overwrites a change it was not yet asked for; on the wire (`hello`, `presence`, `policy-set`) a ceiling the file does not name is RL10's `"settings"` (the settings' defaultMode: `sminos_policy.wire_policy`), and an endpoint's `"settings"` leaves the file without one. O10's RL10 conversation (MAWS's `test/endpoint/rl10/conversation.json`, copied byte for byte to `sminos/tests/rl10-conversation.json`, its commit and blob in `rl10-conversation.source.json`) is replayed against this uplink by `sminos/tests/rl10_conformance.py`, every line as written (MAWS's master at `27e7208a1` carries the threads' lines, a declared channel's, its case 13, and a channel's requests across machines, case 14 (the fifteenth): another machine's session's two requests imported verified and each asked as `reach?` under the channel's id, answered `deliver` and `refuse`, staged by narrowing each target to private, the harness binding what its `add-machine` and `machine-event` scenes make and the fixture's literal thread ids to the ones sminos minted (a `vary`'d `thread`), and the in-process uplink's warnings going to daemon.log, as a daemon's child's do; nothing is amended in the harness), its `PROBES` checked over the whole conversation instead: any line sminos cannot send as the fixture has it fails. Its revocation sets go to `daemon/revoked.json` (0600; whole from the first after each welcome, merged into after, never by an older version; `sminos_rl10.revoked()` raises rather than read an unreadable file as empty). `legacy-key?` is answered from hub.json's `org` and `key` (`legacy_key_path`, the file's one reader), to an endpoint welcomed for the key's own org only, as often as it asks, and the key is in no log line; production endpoints no longer ask, and the reader goes once MAWS drops the exchange from RL10 and its fixture. Nothing on the wire carries a code: `HubLog` uploads this machine's events as stored (`ts`, no `mac`, no `created`, which the endpoint derives from `ts`), and takes each arriving event wrapped `{event, signer, owners?}`, one that is no log event sminos can read, or whose `event` carries `verified`, refused `bad-shape`, the rest stored verbatim with `verified: {signer, owners}` added (`owners` only when sent, as `{id, email}`); an own event the endpoint returns, `created`, `sig` and `attest` added, reads `present` when it echoes the stored one, else `conflict` (`same_uncoded`). An arriving event the endpoint refused for good never comes down; its position does, `spent {project, writer, seq, reason}` (O12 M7b), recorded as a position refused here (`HubLog.spend`: an own writer's, under this machine's name or a former one, through `spend_own`, so a position an event of this machine holds stays that event's and is said, not spent; the writer's later events not held behind it, the vector past it), each said once in daemon.log with its project, writer, seq and reason, and counted per project by `daemon status` on a cut-over machine. `raised`, `settled`, `pending` and `delivery` bodies go as drafts, a settlement kept in `requests-owed.json` before the cutover restored without its `mac`. A welcome that renames the machine renames the requests and the RPCs in place (`rename`), never replacing them: each is the one owner of its file under `daemon/` and of the workers that write it. An RPC's ledger entry keeps its `member`, `device`, `fingerprint`, `context` and `proof` and a `target` derived from the checked RPC (`{kind: machine}` for a spawn, else the session); `rpc-result` names the `opId` beside the nonce, a loose refusal's too; `rpc-ack` settles by the nonce, else by the `opId`; the endpoint's `query` and `tombstone` reach `Rpcs.query`/`Rpcs.tombstone` and are answered `queried`/`tombstoned`, each with the op's binding (`member`, `device`, `fingerprint`, `target`: its entry's, else its in-flight record's; none for an entry kept before the cutover or written by an older daemon). A remote action is bound to its sender and fenced to the launch it was sealed for (O12 M7). The binding and the latest nonce are the op's in-flight record from dispatch on (`Rpcs.flight`, under `op_lock`), and the claim or a refusal the worker keeps is built from it; a copy of a known or in-flight op from another member, or under another fingerprint, is refused `op-conflict`, loose, under its own nonce, saying nothing of the op; an identical one takes the nonce. An RPC on a session carries `context {lane: 'A', session: args.session, launch}`, else `bad-shape` at admission; `plan` adds the launch to every bridge command and decision (`fence`), which the bridge's child refuses `409 launch` when its own differs, before the mod sees it (the RPC fails `launch`; an upload so refused saves nothing); a remote RPC on a session with no bridge is refused `context`, never the supervisor's reply or the inbox, and `resume`, `retire` and `stop` (O10 offers none of them) `unsupported`. A remote spawn's `proof` goes to its verb as `SMINOS_DESK_PROOF` (canonical JSON), which the new session's record keeps as `ownersProof`.

On a cut-over machine the endpoint decides a person's words from what sminos tells it (O12 M6). The uplink sends `member` for every session of this machine in every project known here, relayed or not (`Link.members`, from `Plane.member_rows`: the record's owners, proofs, origin, principal, inference and controller — `@machine` and `terminal` while it has none —, the lane, B by the controller or a `maws` origin awaiting one, and the row's alias, state, title, cwd and worktree, and `launch`, the launch its bridge's status names, kept by the plane's probe, which a cut-over machine's presence carries beside `bridge`), the whole set after each welcome, then each change, `{session, gone: true}` at leave. The endpoint signs an upload as its frame arrives and attests it from the record it holds, and keeps that signature, so the member set goes first in each tick, ahead of every hello, upload and host message, queued in entries of at most 256 KiB and none while the lane holds 4 MiB unsent (a frame carries the record's proofs, which a lineage inherits), nothing that depends on it going until all of it is queued; and the sessions a drawn upload frame carries, a host pass's and the words asked have their frames queued first with their records as they are now (`Link.members_before`: a session that joined since its project was last read is looked for in the project's rows, once per listing; a frame whose member cannot be queued yet is drawn again on a later pass). Every `human` event `_append` stores under this machine's own writer gets an append receipt first, under the writer file's lock (`projects/<id>/receipts/<writer>.jsonl`, `{seq, hash}`, the hash over the stored canonical body; outside `log/`, so never mirrored or uploaded; kept under the writer name used): the writer name is not provenance, a git mirror's merge can bring a `<thisname>/human` line, and only `receipted` events are an own operator's. A revocation set marks every owed event its signer (`verified.signer`: key id, device or member, `sminos_rl10.signer_revoked`) names, asked or not (`revoke_owed`, `delivered_revoke`: the delivery record's `revoked` seqs, its `refused-revoked` outcome recorded first; never delivered, `_owed` leaving it out, and passed by the settled prefix only in order, since a member's devices share `hub/<member>`). Who delivers a person's words there (`words_route`): a `human` event of `hub/<member>`, of another machine's `<name>/human` that arrived with `verified`, or of this machine's own `<name>/human` (a current or former name) whose receipt matches is the endpoint's to decide — the uplink's words pass (`Link.ask_words`, after the tick's upload pass, so an own event has gone up on the socket before it is asked; at a nudge, an import, a verdict, a welcome or an ask's deadline, else every 10 s) sends `words? {id, project, session, event}` (`project` the log that holds it, which the endpoint requires; the stored line less `verified`) for the first owed event of each such writer of each local member in every project known here (`words_due`), queued in entries of at most 256 KiB and none while the lane holds 4 MiB unsent, so a broadcast to many sessions is asked across passes, each ask held, its deadline counted, from when it is queued, and carries out `words {id, verdict}` at once (`deliver_verdict`, under the delivery lock and only while it is still its writer's first owed: `words` the bridge, then a --bg job's supervisor; `peer` the inbox frame; `refuse` nothing, settled `refused-words`); unanswered within 10 s it is a failed attempt (`words_unanswered`, toward the 60 a push has) and is asked again under a new id, and a revocation drops its ask. Every other deliverer (`deliver_next`: the daemon's tick, `say`'s fast path, the uplink's delivery of what it imported) stops such a writer at that event (`gated`: `say` prints `recorded; the endpoint decides its delivery` and nudges the daemon, whose uplink asks), and delivers the other `human` events — a git mirror's, an operator line no receipt bears out (both said in daemon.log), a legacy signer's — as peer messages, never asked; an operator's `send`, to a seat or a seatless session, is recorded and pushed nothing (`SendDelivery.held`: `recorded <ref> for <alias>; the endpoint decides its delivery`); and `push_live` raises rather than decide a log-backed `human` event by its writer with no verdict. Every deliverer checks an event that carries `verified` against `revoked.json` before it pushes it (`WordsGate`, the set read again for each event, so a revocation kept mid-batch stops what follows): a revoked signer's is marked, and while the set cannot be read such an event waits. A session's `send` checks every earlier event of its writer it carries the same way (`SendDelivery.checked`): a revoked one is marked and left out, the valid ones go with it, and one the unreadable set cannot clear holds the send owed (`recorded <ref> for <alias>; it waits behind <ref>, …`). A chat frame, a `send`'s frame (`[sminos message from <sender><label> id=<id>]`, the id `send --wait` looks for unchanged) and a `sminos chat` line carry the label after the sender, from `verified` alone (`sender_labels`): `, owned by <email>` (the id where the endpoint had no email), ` (owners unverified)`, ` (unverified, legacy)`, ` (signed by a revoked key)` however old the event, and ` (unverified)` for an operator-writer event no receipt bears out that is later than the cutover (identity.json's `cutover`: older history reads as before, though delivery still never takes such an event as words); nothing on a machine not cut over. The alias before it is the writer's own claim, so these lines and a retry's pointer (`holder_wake`) write an alias holding any of `,` `(` `)` `"` `→` `[` `]` or a line break, or an angle the peer envelope's closing-tag escape starts at (`<`, `>` and their lookalikes, `ALIAS_ANGLES`), as a JSON string literal (`frame_alias`), in which those angles and U+0085, U+2028 and U+2029 are `\uXXXX` escapes, so nothing on the way to an inbox rewrites it and any other bare, as before: the label always stands outside it, and a reader (MAWS's pane, `manager_window.frames`) decodes an alias that opens with `"` and reads a bare one to its first `,` or ` (`.

A machine's notice (contract X8 of `docs/doperpowers/specs/2026-11-17-sminos-channels-and-threads-design.md`; EN.G1's plan `docs/doperpowers/plans/2026-11-21-sminos-environments-en-g1.md`, Interfaces §1 and §2) is a `human` event under a machine's human writer whose `notice` names the program that speaks: `say --notice <program>` (`NOTICE_PROGRAM_RE`, an empty value refused too; refused in a session, exit 2; refused with exit 1, nothing recorded, on a machine whose own writer `notice_of` would not mark, since the event would then read as a person's words, and 1 is the failure a host's delivery goes on from, where 2 would have it send the text again unmarked) puts it on every event the call appends, a tag's, a broadcast's and an `--in` note's, and devcloud's hosts pass `devcloud`. `notice_of` is the one test (the writer's machine whole by `NOTICE_MACHINE_RE`, MAWS's machine-name grammar, and never `hub` or `legacy` in any case, so sminos and MAWS mark the same events) and `notice_sender` the one sender string, `<program>@<machine>`. It is nobody's words: `owner_event` is false for it (so the manager's `OwnerWords` leaves it out), and `sminos_control._routes` sends it as the inbox frame from its sender, with no reply line, never through the bridge or a supervisor, for a verdict of `words`, `peer` or none — the VM's own endpoint answers `words` for the VM's own line, and without that guard a broadcast would reach a session there as its human's prompt. What authorizes a push is unchanged: it is asked of the endpoint as any `human` event of its writer is, and the reach gate (`ReachGate.applies`) treats it as it treats that writer's events. `frame_of`, `holder_wake`, `chat_line` and the TUI (`sminos_tui.sender_of`) show the sender, and it is always a chat frame, a `msg_id` on it included (`frame_of`, `frame_landed`); it stays a chat event, shown and counted, and wakes a stopped thread it is addressed to as any addressed event does. A direct `send`, `send --wait` or `resume` pushes the writer's owed queue as runs (`SendDelivery.runs`, `push`, `landed`): a new run wherever the notice sender changes between neighbours (`run_sender`: a marked event's `notice_sender`, none for an unmarked one, so two programs' notices are cut too), each pushed by its own last event's route and settled as it lands, so a notice never rides inside an operator's verb on the bridge and the settled prefix never passes an event not handed over; a run whose close-out is uncertain is settled and what follows it stays owed, and where that run went ahead of the verb's own the sender is told which, and that its message stays queued for the daemon (`SendDelivery.uncertain`, `uncertain_ahead`). `say --exit-held` exits `EXIT_HELD` (3) where a tagged recipient's line was a held one (`deliver_say` returns those recipients: a local hold whose `why` is in `HOLD_WORDS`, or another machine's published `held`, `remote_held`), recording and printing as without it; it is how a host's notice goes on to the project when its owning thread is held (devcloud's `boot/devcloudlib/notices.py`).

`sminos spawn --on <vm>|new` opens a session on a devcloud VM from a Mac (`new` from a session only; a placement the operator makes by hand, `devcloud vm ssh <vm> -- sminos spawn …` with no `--asked-from`, is `spawn` as it always was) (EN.G1's plan `docs/doperpowers/plans/2026-11-21-sminos-environments-en-g1.md`, Interfaces §7 and §8; `sminos_on.py`, which holds all of it but the seams in `cmd_spawn`). The Mac side refuses what it can by itself before devcloud runs, in §7's order: usage (`--wait`, `--settings`, a relative `--cwd`, `--vm-*` without `new`, which `cmd_spawn` refuses without `--on` too, a `--stamp` `spawn` would refuse), this machine a devcloud host, not enrolled, or named itself; from a session, no address, a project this enrollment does not carry (`sminos.not_carried`, the very test `sminos_uplink.hub_projects` makes of each project), or a reach that is not known to be the default (`reach_refusal`: the record as it stands, never rebuilt, a missing, unreadable or unsettled one refused — `sminos.provenance_settled` is `ensure_record`'s own test, the engine's record of the running process read afresh by `running_now`, and none found unsettled whatever the record rests on — then access `listed` and no shares, read again before every call to the VM); devcloud's CLI found as `owned_by` finds it, at 0.18.0 or later. For `new`, from a session only, the project is `<owner>/<repo>@<branch>` of the caller's own worktree, its origin read as configured (`git config --get remote.origin.url`, never `remote get-url`, which applies `insteadOf`) and asked by the exact ref at that url (`git ls-remote <url> refs/heads/<branch>`, the branch from `symbolic-ref`'s full ref, since `--short` answers `heads/<branch>` beside a tag of that name; the worktree's commit), unless `--vm-project` names the projects; then `devcloud vm up --enroll --keep --expect-creator=<short> [--label=<alias>] --project=…`, each value one word as devcloud's parser reads it, its lines passed through, the host read from its one `ready` line, the only line that starts the VM side; every refusal after it (`Call.refuse`: `up`'s failure, a stop, an unusable `ready` output among them) says a VM its `created` line named and its recount's own line (`DELETED_RE`) did not say deleted is kept, whose and how it ends, and, where it named none after its caps line short of a cap's or a provider's refusal, ends saying one may exist, `devcloud vm ls` showing it, before any retry. The VM side is `devcloud vm ssh <vm> -- env -u CLAUDE_CODE_SESSION_ID sminos spawn --asked-from=<json> --cwd=<dir> … -- <alias> -` (the session variable cleared there for that call alone, `vm up` keeping the caller's; each value as one `--flag=value` word and the positionals after `--`, so the VM's parser reads what the Mac's read: `--brief=--review`, an alias `-a`), the task on standard input as the Mac's own spawn read it, taken as sent there (`stdin_body` strips nothing under `--asked-from` and decodes as the Mac encodes, `surrogateescape`; an empty one refused under the outcome line), bounded (`SMINOS_ON_TIMEOUT`, one deadline for the run and the reading of its output: past it a descendant still holding the output is left, and an outcome read from output that never ended is not known); `cmd_spawn` under `--asked-from` refuses on a machine not enrolled or of another org, where the Mac inferred the directory (`~/Developer/GitHub/<repo>`) on another repository's checkout, and, `--cwd` given or not, where the project the spawn would be in is one this enrollment does not carry (`hold_to_org`, `not_carried`; `why` `other`, exit 1), names the spawner in the preamble's `{{BY}}` and the `joined`'s `by` (`spawn_fresh`'s `asked`; the record a terminal spawn's), prints no banner, and ends, for every way it ends after the request was read, with one outcome line, `sminos-spawn <nonce> <json>` (`Answering`, which says a success that would not read whole as a refusal), except once the launcher returned a job (`spawn_fresh` marks the request `launched`; `read_request` builds the request from the protocol's fields alone, so no key off the wire is taken for a mark): then any end but a whole success, an exit or an exception alike, prints no line and names the job on standard error, and the Mac says the outcome is not known; The org frame's `locations` and `complete` (the registry's §D, §E.3; `sminos_uplink.keep_org`) are kept with the directory in the one atomic, durable write of org.json (`write_json(durable=True)`: the file synced before the rename, its directory after), under those keys as the frame carries them: a frame whose `locations` reads (`{gen, at}`, `gen` an integer; `frame_locations`) replaces the held ones whole, one without them, or with another shape, keeps them, and `complete` is the frame's alone. Once that write is done, and only then (a failed sync sends nothing), the Link answers `locations-kept {gen}` on the frame's own connection, in order on its lane (`on_org`), for the endpoint to release what waits on that gen; keep_org forgets the caches, so the uplink's next resolution reads the new statements and anchors. Unknown is not empty (`sminos.locations_unknown`): on an enrolled machine whose last kept welcome listed `locations` (`daemon/audiences.json`, kept at the uplink's every welcome and at `daemon probe`'s; `sminos_audience.advertised`: no file, or one that cannot be read, is not a listing) while org.json holds none — no frame since the upgrade, or the file gone — a session last a member of a project other than the one its directory's files give is in that one (`last_project`: the project of its latest own membership event, joined or ended, and for a `moved` retirement the destination it names, so a move whose destination's `joined` was never written is still that move; `_session_project`), so no reconciliation moves it until a frame decides and a session resumed meanwhile rejoins it; a session recorded nowhere resolves by files and joins. `join` and the session-start guidance say why it is there, never an override it has not got. Beside an endpoint whose welcome lists no such capability, resolution is today's. The upgrade writes no migration: a declared folder's sessions move from the machine's project into its minted one by `_reconcile`, once (`sminos/tests/test_locations_kept.py`).

Leaving a project (the registry's §E.4; `sminos_uplink.Leaving`, `Link.leave_pass`): a project the machine follows with no folder here (`Link.may_leave`: not held, no known checkout as it is now — a registered root or declared location that still resolves to it, a directory a session joined from — and no machine's project, by the directory's kind or its id; a registered root whose folder is gone is no folder, and a registered root or declared location this process may not read, `read_refused`, is an unknown that counts as a folder) has a count of seconds that runs only while the uplink is connected and that connection's last org frame says `complete: true` and lacks the project. It stands still while disconnected (nothing past a connection's last scan is counted), before a connection's first frame, under a frame that is incomplete or has no `complete`, and over a gap between two scans longer than `LEAVE_STEP_MAX` (60 s: a machine asleep is not counted). A frame ends the state before it at the moment the reader took it, not when it was handled, and takes effect whether or not its org file could be written; a scan counts no further than the receipt of the oldest frame still queued, and decides nothing while a close is queued (`Link.unread`). A frame that lists the project sets its count to zero and takes it out of the kept set; at `LEAVE_AFTER_S` (86,400) it enters the set, and the scan ends the connection so the next one does not open it (as a retirement does). The set is read by `hub_projects` and by `sminos.has_left`, which `org_scope` and `list`'s widened scope (`--org`, `--machine`, `--state`, `--here`) apply, so a project that left is in neither; its log stays, and one that left and is held or has a folder here again leaves the set at the next scan and is opened at it. The counts and the set live in `daemon/leaving.json` (`{counted: {id: seconds}, left: [ids]}`, written durably by the uplink alone: at a frame that changed them, at each change to the set, and every `LEAVE_SAVE_EVERY` while a count runs; what depends on a write waits for it — memory is the truth, and a write that fails, before its rename or after it (the directory's sync), is owed and tried again at each scan, the departures and returns it carries reported (the connection ended for a departure, a return opened) only by the first scan whose write succeeds, and a frame whose reset is not kept has its `locations-kept` held until then; whatever the file held meanwhile, that write makes it memory's), so they survive a restart, and a write a crash loses loses counted time, never adds it (`sminos/tests/test_leaving.py`, its clock `uplink.leave_clock`). A project the directory marks retired leaves at once, as before.

A verb's prose given as `-` is read from standard input (`STDIN_BODIES`, `stdin_body`, applied in `main` before any migration: say's text, send's and resume's msg, spawn's and fill's task, steer's text, compact's instructions), the text whole less one trailing line ending, refused from a terminal or when empty, so a heredoc with a quoted delimiter carries a body the shell would change inside double quotes; the hooks module's backtick guard refuses the double-quoted form when a backtick in it is live (`sminos/tests/test_stdin_bodies.py`).
