# sminos/skills/sminos/scripts/ — the sminos CLI, the daemon and its uplink

A path here is named from `sminos/` when it is the plugin's own file; `docs/`, `sminos/…` and `to-human/…` paths are the repository's.

With a remote in `.smns` the log is a git working tree mirrored through it, and `sminos daemon` (one per machine; `daemon install` writes a launchd agent on macOS, a systemd user unit on Linux) syncs the mirror, delivers remote messages to local members, and publishes their state, so a project spans machines.

A project whose `.smns` names a desk hub instead (`project init --hub`, on a machine enrolled by `sminos hub enroll`, which reads the enrollment code — it carries the org key — from a hidden prompt or stdin and refuses it as an argument; `hub show` prints the machine's identity, never a secret; the file names the org alone, `"hub": {"org": …}`, each machine's enrollment the hub's URL, as doperpowers' own `.smns` does) syncs through the hub alone, never through git: `daemon run` supervises `daemon uplink`, a child process holding the hub's stream, which uploads the machine's own writers sealed with authentication codes and verifies every event the hub sends before it enters the log, and the machine writes under its enrolled name. Over the same stream the uplink serves the desk's session plane and its RPCs, the daemon being the execution boundary: presence from the engine's session records, each subscribed session's transcript and its bridge's stream joined in one order, the bridges' pending requests and their settlements, and the outcome of each delivery of a message from outside the machine; presence carries what each session's bridge can do (`capabilities`) and the machine's `desk` (its sminos version, its RPCs), a `read` frame is answered on its subscription from the bridge (an `mcp` read with the servers the session's project disables added: `projects[<key>].disabledMcpServers`, the one key read of the engine's global config, the file and the key chosen as the engine chooses them — the legacy `.config.json` while it is nonempty, and a linked worktree's primary checkout), and a desk command's run and a side question's answer go up as `op`, each only to a hub whose welcome lists its kind; an RPC (steer, interrupt, stop, answer, decide, model, compact — its instructions passed to the bridge —, command, btw, stop-agent and tell — one subagent the session's tree holds as running, by its id, else the name of exactly one running agent (`unknown-agent`, `ambiguous-agent`), the id it resolved passed to the bridge, which acts on that agent alone —, spawn, retire, resume, media — an upload saved under the session's live working directory and handed to its bridge, which reads it in by a Read of its own —) runs only once its code, the machine, project, and session it names, the at-most-once ledger (`daemon/rpcs.json`, keyed by the RPC's operation id — RL4's `opId`, which carries `opCreated` and is refused `expired` past `OP_HORIZON`, a day less an hour, so pruning never reopens one; else its nonce, as DX6 sends it — the hub's `rpc-result` and `rpc-ack` keeping the nonce, an op's answer going up under its latest copy's, a copy that arrived while the op was in flight or claimed included; a tombstoned op refused `tombstoned`, and `query`/`tombstone` on the daemon's controller answering what became of an op, claim and tombstone one transition under one lock with the workers' `flight`; `sminos rpc-query [--created T] -- <opId>` prints the ledger file's view, without `flight` (`--` since a base64url id may start with `-`)), its age, the machine's policy, and, for an answer or a decision, the digest of the request still pending all hold (a scoped allow's rule, `decide.scope`, is resolved from that request's own suggestions, never from the browser: `session`, or the suggestion's own `localSettings`), and its result is sent again until the hub acknowledges it. The policy (`daemon/policy.json`, set by `sminos daemon policy [--read-only on|off] [--ceiling MODE|settings]`) can make the machine read-only — no RPC runs, nothing from outside is delivered — and caps a spawn's permission mode; Resume runs `claude --bg --resume <session>` with no other flag once no process of the machine holds the session, and stops any copy the engine starts instead; a session whose record's controller is lane B is refused `lane-b` (reopening a MAWS lane B session is MAWS's), as is any op an observer's bridge refuses `lane-b`, a refusal its child kept and a restart reads back included. Such a project's remote keeps only the log's archive, which the one machine the hub designates for it writes on a schedule (`SMINOS_ARCHIVE_EVERY`, 15 minutes) from a clone at `projects/<id>/archive/`, never read back into the log.

Every enrolled machine follows every project of its org (the hub's `org` frame, kept at `daemon/org.json`), so `sminos list --org|--here|--project|--machine|--state [words]`, `find`, `projects` and `machines` show who works on what across the org, and `@short`, `@alias#short` and `@<project>/<alias>` reach any session there, recorded in both projects' logs (a bare `@alias` stays in the sender's project); design `docs/doperpowers/specs/2026-10-18-smns-org-directory-design.md`.

A machine whose MAWS `mawsd` endpoint serves RL10 is taken off the network by it (O12 phase 2, M5; plan `docs/doperpowers/plans/2026-10-27-p5-o12-sminos-owners.md` in MAWS, the frames O10's Interfaces §D). `sminos_rl10.find` reads the endpoint's `rl10.json` (`$MAWS_USER_DATA/mawsd/endpoint/`, else O2's platform default; `SMINOS_RL10` for a test): a regular file of mode 0600 owned by this uid, protocol 1, a token of 64 hex characters and a socket, anything else no endpoint, said once in daemon.log. Before the cutover `daemon run`'s supervisor only probes it, beside the hub's uplink and never in its place (`sminos daemon probe`: dial, `hello` with the token, the welcome; backing off from 1 s to a minute, from 1 s again when rl10.json changes): a refusal, a wrong token, silence, or a welcome whose identity is not whole (org, hub, name, ref and enrolled: an endpoint not enrolled yet, which `daemon status` says) leaves the hub's stream as it is. A whole welcome cuts the machine over, once and for good: `daemon/identity.json` (0600; org, hub, name, former, ref, enrolled, cutover, build; `former` this machine's own map of names to the sessions held under them, copied from hub.json at the first welcome, a rename the endpoint made adding `sessions_under(old)` before the replace, and never shrinking) is read before hub.json by `enrollment`, `machine_identity`, `enrolled_at`, `hub show` and `project init --hub`; the hub's uplink is stopped, and the child (`daemon uplink`) speaks RL10 alone from then on — `Link` with `coded` off over a `SocketTransport` (the reader, and one `SocketLane`: newline-delimited frames of at most 1 MiB, DX2's parts beyond; a frame written is taken, its continuation run on write, everything restated after each welcome; every session kind sent) — and while the endpoint is not running nothing runs (`daemon status`: `cut over; the endpoint is not running`; daemon.log at once and hourly). `hub enroll`, `check` and `leave` exit 1 there, the enrollment being the endpoint's, and none dials the hub; removing identity.json undoes the cutover. The endpoint's `policy` (the welcome's, and each frame) is the machine's: written to `daemon/policy.json` with the endpoint's last word kept beside it (`endpoint`), so a `daemon policy` change made here goes up as `policy-set` and the file settles on the answer, and a welcome never overwrites a change it was not yet asked for. Its revocation sets go to `daemon/revoked.json` (0600; whole from the first after each welcome, merged into after, never by an older version; `sminos_rl10.revoked()` raises rather than read an unreadable file as empty). `legacy-key?` is answered from hub.json's key, to an endpoint welcomed for the key's own org only, as often as it asks, and the key is in no log line. On RL10 nothing carries a code and nothing is sealed, verified or indexed by nonce (the key is None): `HubLog(..., coded=False)` uploads this machine's events as stored (`ts`, no `mac`, no `created`, which the endpoint derives from `ts`), and takes each arriving event wrapped `{event, signer, owners?}`, the shape checks as on DX2, one whose `event` carries `verified` refused `bad-shape`, the rest stored verbatim with `verified: {signer, owners}` added (`owners` only when sent, as `{id, email}`); an own event the endpoint returns, `created`, `sig` and `attest` added, reads `present` when it echoes the stored one, else `conflict` (`same_uncoded`). `raised`, `settled`, `pending` and `delivery` bodies go as drafts (`Requests.seal`, `outcomes.message` with no key), settlements the hub's uplink left owed in `requests-owed.json` too (restored without their `mac`). A welcome that renames the machine renames the requests and the RPCs in place (`rename`), never replacing them: each is the one owner of its file under `daemon/` and of the workers that write it. `Rpcs(..., coded=False)` skips the code check alone; its entries keep the RPC's `member`, `device`, `fingerprint`, `context` and `proof` and a `target` derived from the checked RPC (`{kind: machine}` for a spawn, else the session); `rpc-result` names the `opId` beside the nonce, a loose refusal's too; `rpc-ack` settles by the nonce, else by the `opId`; the endpoint's `query` and `tombstone` reach `Rpcs.query`/`Rpcs.tombstone` and are answered `queried`/`tombstoned`.

What a session sends its person stays on a cut-over machine (O12 M8): `append_host` puts the host events (`message`, `question`, `answered`) of its own project and every hub project in the host store, `projects/<id>/host/<writer>.jsonl` beside `log/` (`host_store_holds`; the log's event shape and writer names, the store's own seqs, the `(kind, src)` rule, an answer under its asker's writer, a question found in either store), never in the log the hub carries, and git-mirrored and local projects keep them in their log; the log's host events from before the cutover stay where they are, and `chat --host` merges both by time (`host_read`). The uplink's host pass (`Link.host_pass`, RL10 only) sends each up as a sub-less session-lane `host` message, body `{id: {writer, seq}, event}`, whether or not anyone subscribes (the endpoint derives its `wrote` notification from these), past the project's cursor in `uplink.json` (`host_sent`, moved once written), and each session's last 50 again whenever a connection opens the project; a main subscription carries the session's host events in its own stream (`host`) and its snapshot (`host`: the last 50, `sminos.host_events_of`). Nothing of `host/` is in the vector, an upload or a resend.

Each session sminos joins has a record of its own on the machine (O12 M1, the remote layer's RL6; plan `docs/doperpowers/plans/2026-10-27-p5-o12-sminos-owners.md` in MAWS), kept by `sminos_records.py` at `$SMINOS_HOME/session-records/<session>.json`, mode 0600: its `owners` (member ids, or `@machine`: this machine's owners, a token RL10's endpoint resolves against the org state), `ownersProof`, `origin` (`terminal`, `maws` with its `requester`, or `sminos-spawn` with its `spawnerSession`), `principal`, `inference` (a config-dir slot, or a route naming a file or a gateway's `base-url:<scheme>://<host>[:<port>]`, never a secret), `created`, `former`, its `basis` — the evidence it rests on, strongest first: `launch`, `lineage`, `hook`, `default` — and `source`, the basis when that evidence is final, else `default`, provisional. Every path that joins a session makes sure of its record first (`sminos.ensure_record`), and a record is replaced, its `controller` kept, only by strictly stronger evidence (the basis's rank, then final over provisional), so equal evidence read twice never flips it. A spawn's provenance is fixed before the child exists: `spawn_fresh` writes `session-records/pending/<launch>.json` and launches with `env.SMINOS_LAUNCH` in the merged settings file it now always writes; the child's first SessionStart, a startup, binds the launch to its own session id with no lock (`pending/<launch>.session`, created whole by a link) before the hook does anything else (`claim_launch`, ahead of the migration), and its hooks claim it by one rename until one succeeds, as the spawner may once the harness names the child, the claim honoured for the bound session alone, so a `claude` the seat's Bash starts, inheriting the variable, claims nothing even when the seat's claim waited out a held lock. A continuation's is its lineage's, its predecessors' alone (its own publications are never evidence): the first final record along it (`hand_off`, the `continued` retirements, a job's live predecessor), else the latest `joined` among them that publishes, else the first provisional record. The hook's or the bridge child's reading of the session's own environment (`hook`: `maws` when its host marked it, the route from `ANTHROPIC_BASE_URL`, else the slot from `CLAUDE_CONFIG_DIR`) speaks only for a session no launch and no lineage speaks for; else the machine's defaults. A desk RPC's spawn is its member's (`SMINOS_DESK_MEMBER`); a `sminos spawn` inside a session copies that session's owners, proofs, principal and inference (provisional when its are), a seat with settings of its own running on the merged launch file; `launch_env` drops `SMINOS_LAUNCH`; the daemon sweeps a pending launch, and a binding, after a day. `controller {lane, since}` is current state beside it, written on an existing record by `set_session_controller` and never copied: each launch's bridge child relays its lane verdict there (O12 M3: `B` for a MAWS lane B session, `A` otherwise; nothing while unresolved), retrying until the record exists; `launch_env` drops `MAWS_LANE`, so a seat a lane B session spawns is no observer. Only `origin`, and `owners` that name members only, leave the machine, on a `joined`, and only once the record is final: a member whose latest publishing `joined` does not carry what its record publishes now (it became final, was replaced, or an append failed) is joined again carrying it, checked on every pass (from the log's one-pass index when a reconciliation holds the log), and every `joined` takes what it publishes from the record as it is under the session file's lock, so a writer that paused never appends older provenance; `@machine` never leaves it, so owners that hold the token are left off and read back as the machine's, and as an owner the token stands alone (every record writer refuses a list mixing it with member ids, which that readback would lose); `_projection` and `_member` read them from the latest `joined` along the lineage that publishes them, the record winning for a member of this machine, `@machine` and `terminal` where nothing says; `list --json` carries `owners` and `origin` for every member, and `principal`, `inference` and `controller` for this machine's, except in the org's view (`--org`).

The CLI is `skills/sminos/scripts/sminos.py` with `sminos_daemon.py` (mirror and delivery), `sminos_hub.py` (enrollment), `sminos_rl10.py` (the endpoint, RL10: discovery, its connection, the cutover's identity, the revocation set), `sminos_uplink.py` and `sminos_hublog.py` (the hub's stream, and one project's log plane over it; the uplink posts through two sender lanes, each a thread on one kept connection — the log plane's frames on one, the session plane's, the requests' and the RPC results on the other, a project's held until its `hello` is answered — so a POST the hub holds, or a fresh TLS handshake, stops neither the main thread's pump nor the other lane, and each lane writes a daemon.log line for every connection it dials and closes, with the POSTs it carried; a POST's 200 names the frames the hub refused whole (DX2's `refused`, MAWS #88), so a settlement, a compaction or an op message refused `not-open` stays owed, its project is opened again and it goes behind that hello, and what is owed is kept in `daemon/requests-owed.json` and `daemon/rpcs-owed.json` (versioned; another version's file is ignored), so an uplink restart sends it again even when its bridge is gone — `sminos_owed.py`), `sminos_plane.py` (the session plane: presence and subscriptions, each transcript's offset index and its worker thread, so a subscription pages a session's whole history — an ended one's too — off the uplink's thread; the build — the index, the loop's jobs ledger and its chain — saved under `daemon/plane/` as it grows and at the uplink's stop, and loaded by the next process only while its CRC still matches the file's prefix, so a restart costs an open a load, not a parse; a warmer that keeps the live members' builds current in the background, bounded so the opens never wait on it — behind any foreground job of its transcript, `WARM_PARALLEL` jobs at once, none started while an open awaits its snapshot; and each transcript's live chain, so the snapshot, its pages and each row mark the rows an Esc or a /rewind left off it (`offChain`, `onChain`), the rows the engine no longer holds), `sminos_jobs.py` (the subagents' status, background jobs and MCP names derived from the rows, and `output`'s containment; pinned with MAWS's fake machine by `sminos/tests/dx4-jobs.json`; plan `docs/doperpowers/plans/2026-10-17-desk-dc8-machine.md`), `sminos_subagents.py` (`list --subagents [member] [--done N] [--depth N] [--stall MIN]`, the view that stands in for the engine's ListAgents, which the guide tells a session to use instead, and the one cheap line plain `list` ends with inside a session — the bridge's running count, else the open turns of the running process from their tails, never the deep reads; each subagent's lifecycle — running, waiting on background, stalled, orphaned, completed, failed, stopped — from the engine's word where the session's bridge answers (GET /agents, the engine list's `status` the bridge mod carries; an end older than a revival's open turn yields to the rows), else from the disk: the meta, the transcript's tail read backwards for whether its turn is open, what is in flight and since when, its background tasks through `sminos_jobs`' ledger, the TaskStops and stop notes of its parent loop and the main loop — read once a view, only back as far as asked, found by bisection on the rows' timestamps — and the session process's start, before which nothing still runs; its activity beside it; `--json` an envelope `{self, scope, counts, agents, notes}`, every note saying what could not be read), `sminos_requests.py` and `sminos_outcomes.py` (pending requests and their settlements, and delivery outcomes, as the hub's sealed messages), `sminos_policy.py` (the machine's policy and its known checkouts), `sminos_rpc.py` (the RPCs: their checks, the ledger, execution, and the outcomes that follow them — a compaction's, a desk command's run and a side question's answer as DX4 `op`, a `/reload-plugins` finished by its bridge answering from another child; a stop-agent's and a tell's answer is their outcome, reconciled after a stop from the child's kept answer as a steer's is; an upload's attachments' states as `op` too; plan `docs/doperpowers/plans/2026-10-15-desk-dc7-controls.md`), `sminos_media.py` (a desk upload's files, MW5: written under `<cwd>/.claude/desk-uploads/<session>/` through a walk from `/` that follows no link, each created exclusively under `<op>.<n>.<ext>` (the RPC's operation id, its nonce when it has none), the extension its bytes' signature names, a refused save rolling back only the files the upload made its own; the repository's common `info/exclude` given `**/.claude/desk-uploads/` through the same walk, a linked or irregular exclude refused; each root recorded at `daemon/uploads/<session>.json` before anything is written, and swept, again following no link, by the bridge kept file's rule), `sminos_codes.py` (the codes, pinned to the hub's vectors by `sminos/tests/codes_parity.py`), `sminos_archive.py` (the archive), `sminos_marks.py` (the to-human mark grammar, ported from `to-human/hooks/mods/to-human.tsx` and pinned by `sminos/tests/marks_parity.py`), `sminos_bridge.py` (the child the bridge mod spawns, serving the session's endpoint at `$SMINOS_HOME/bridge/<session>.sock`, and `sminos watch`), `sminos_control.py` (`steer`, `interrupt`, `stop`, `model`, `compact`, `command`, `read`, `decide`, `answer`, and a delivery's last hop to a live session: the bridge, else a `--bg` job's supervisor `reply` for a human's message, else the inbox frame), and the chart and TUI; a session the bridge mod runs in is watched and driven from any terminal on the machine with `sminos watch|steer|interrupt|stop|model|compact|command|read|decide|answer <member>`, its protocol DX5 in `docs/doperpowers/plans/2026-10-15-arkho-desk-c2-bridge.md`; tests `sminos/tests/run-sminos-tests.sh`, which isolate `HOME` and `SMINOS_HOME` — a working copy's CLI run against the real `~/.claude/sminos` performs the one-way import of the old per-host `chats/` on its first call; `sminos/tests/bench_scale.py` measures the daemon's tick, both daemon processes' CPU and an import burst on a synthetic machine at the owner's Macs' scale, against any copy of the scripts (before and after a change).
