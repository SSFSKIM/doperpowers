# sminos/skills/sminos/scripts/ — the sminos CLI, the daemon and its uplink

A path here is named from `sminos/` when it is the plugin's own file; `docs/`, `sminos/…` and `to-human/…` paths are the repository's.

With a remote in `.smns` the log is a git working tree mirrored through it, and `sminos daemon` (one per machine; `daemon install` writes a launchd agent on macOS, a systemd user unit on Linux) syncs the mirror, delivers remote messages to local members, and publishes their state, so a project spans machines.

A project whose `.smns` names a desk hub instead (`project init --hub`, on a machine enrolled by `sminos hub enroll`, which reads the enrollment code — it carries the org key — from a hidden prompt or stdin and refuses it as an argument; `hub show` prints the machine's identity, never a secret; the file names the org alone, `"hub": {"org": …}`, each machine's enrollment the hub's URL, as doperpowers' own `.smns` does) syncs through the hub alone, never through git: `daemon run` supervises `daemon uplink`, a child process holding the hub's stream, which uploads the machine's own writers sealed with authentication codes and verifies every event the hub sends before it enters the log, and the machine writes under its enrolled name. Over the same stream the uplink serves the desk's session plane and its RPCs, the daemon being the execution boundary: presence from the engine's session records, each subscribed session's transcript and its bridge's stream joined in one order, the bridges' pending requests and their settlements, and the outcome of each delivery of a message from outside the machine; presence carries what each session's bridge can do (`capabilities`) and the machine's `desk` (its sminos version, its RPCs), a `read` frame is answered on its subscription from the bridge (an `mcp` read with the servers the session's project disables added: `projects[<key>].disabledMcpServers`, the one key read of the engine's global config, the file and the key chosen as the engine chooses them — the legacy `.config.json` while it is nonempty, and a linked worktree's primary checkout), and a desk command's run and a side question's answer go up as `op`, each only to a hub whose welcome lists its kind; an RPC (steer, interrupt, stop, answer, decide, model, compact — its instructions passed to the bridge —, command, btw, stop-agent and tell — one subagent the session's tree holds as running, by its id, else the name of exactly one running agent (`unknown-agent`, `ambiguous-agent`), the id it resolved passed to the bridge, which acts on that agent alone —, spawn, retire, resume, media — an upload saved under the session's live working directory and handed to its bridge, which reads it in by a Read of its own —) runs only once its code, the machine, project, and session it names, the at-most-once ledger (`daemon/rpcs.json`), its age, the machine's policy, and, for an answer or a decision, the digest of the request still pending all hold (a scoped allow's rule, `decide.scope`, is resolved from that request's own suggestions, never from the browser: `session`, or the suggestion's own `localSettings`), and its result is sent again until the hub acknowledges it. The policy (`daemon/policy.json`, set by `sminos daemon policy [--read-only on|off] [--ceiling MODE|settings]`) can make the machine read-only — no RPC runs, nothing from outside is delivered — and caps a spawn's permission mode; Resume runs `claude --bg --resume <session>` with no other flag once no process of the machine holds the session, and stops any copy the engine starts instead. Such a project's remote keeps only the log's archive, which the one machine the hub designates for it writes on a schedule (`SMINOS_ARCHIVE_EVERY`, 15 minutes) from a clone at `projects/<id>/archive/`, never read back into the log.

Every enrolled machine follows every project of its org (the hub's `org` frame, kept at `daemon/org.json`), so `sminos list --org|--here|--project|--machine|--state [words]`, `find`, `projects` and `machines` show who works on what across the org, and `@short`, `@alias#short` and `@<project>/<alias>` reach any session there, recorded in both projects' logs (a bare `@alias` stays in the sender's project); design `docs/doperpowers/specs/2026-10-18-smns-org-directory-design.md`.

Each session sminos joins has a record of its own on the machine (O12 M1, the remote layer's RL6; plan `docs/doperpowers/plans/2026-10-27-p5-o12-sminos-owners.md` in MAWS), kept by `sminos_records.py` at `$SMINOS_HOME/session-records/<session>.json`, mode 0600: its `owners` (member ids, or `@machine`: this machine's owners, a token RL10's endpoint resolves against the org state), `ownersProof`, `origin` (`terminal`, `maws` with its `requester`, or `sminos-spawn` with its `spawnerSession`), `principal`, `inference` (a config-dir slot, or a route naming a file or a gateway's `base-url:<scheme>://<host>[:<port>]`, never a secret), `created`, `former`, and `source`, how it was established. The provenance is written once, by whichever path first joins the session (`sminos.ensure_record`): a spawn's, fixed before the child exists — `spawn_fresh` writes `session-records/pending/<launch>.json` and launches with `env.SMINOS_LAUNCH` in the merged settings file it now always writes, and the child's first SessionStart, a startup, claims it by one rename before the hook does anything else (`claim_launch`, ahead of the migration), else the spawner does once the harness names the child; a continuation's, its predecessor's record (`hand_off`, or the `continued` retirements and a job's live predecessor); the first `joined` along its lineage carrying owners; the hook's or the bridge child's reading of the session's own environment (`hook`: `maws` when its host marked it, the route from `ANTHROPIC_BASE_URL`, else the slot from `CLAUDE_CONFIG_DIR`); else the machine's defaults, `source: default`, provisional — and stays provisional when a spawn or a continuation copies it, until final evidence replaces it. A desk RPC's spawn is its member's (`SMINOS_DESK_MEMBER`); a `sminos spawn` inside a session copies that session's owners, proofs, principal and inference, a seat with settings of its own running on the merged launch file; `launch_env` drops `SMINOS_LAUNCH`; the daemon sweeps a pending launch unclaimed for a day. `controller {lane, since}` is current state beside it, written on an existing record by `set_session_controller` and never copied. Only `owners` and `origin` leave the machine, on a `joined`, and only once the record is final (a member whose record became final after it joined is joined again, once, carrying them); `_projection` and `_member` read them from the first `joined` along the lineage that carries them, as `by` is read, the record winning for a member of this machine, `@machine` and `terminal` where nothing says; `list --json` carries `owners` and `origin` for every member, and `principal`, `inference` and `controller` for this machine's.

The CLI is `skills/sminos/scripts/sminos.py` with `sminos_daemon.py` (mirror and delivery), `sminos_hub.py` (enrollment), `sminos_uplink.py` and `sminos_hublog.py` (the hub's stream, and one project's log plane over it; the uplink posts through two sender lanes, each a thread on one kept connection — the log plane's frames on one, the session plane's, the requests' and the RPC results on the other, a project's held until its `hello` is answered — so a POST the hub holds, or a fresh TLS handshake, stops neither the main thread's pump nor the other lane, and each lane writes a daemon.log line for every connection it dials and closes, with the POSTs it carried; a POST's 200 names the frames the hub refused whole (DX2's `refused`, MAWS #88), so a settlement, a compaction or an op message refused `not-open` stays owed, its project is opened again and it goes behind that hello, and what is owed is kept in `daemon/requests-owed.json` and `daemon/rpcs-owed.json` (versioned; another version's file is ignored), so an uplink restart sends it again even when its bridge is gone — `sminos_owed.py`), `sminos_plane.py` (the session plane: presence and subscriptions, each transcript's offset index and its worker thread, so a subscription pages a session's whole history — an ended one's too — off the uplink's thread; the build — the index, the loop's jobs ledger and its chain — saved under `daemon/plane/` as it grows and at the uplink's stop, and loaded by the next process only while its CRC still matches the file's prefix, so a restart costs an open a load, not a parse; a warmer that keeps the live members' builds current in the background, bounded so the opens never wait on it — behind any foreground job of its transcript, `WARM_PARALLEL` jobs at once, none started while an open awaits its snapshot; and each transcript's live chain, so the snapshot, its pages and each row mark the rows an Esc or a /rewind left off it (`offChain`, `onChain`), the rows the engine no longer holds), `sminos_jobs.py` (the subagents' status, background jobs and MCP names derived from the rows, and `output`'s containment; pinned with MAWS's fake machine by `sminos/tests/dx4-jobs.json`; plan `docs/doperpowers/plans/2026-10-17-desk-dc8-machine.md`), `sminos_subagents.py` (`list --subagents [member] [--done N] [--depth N] [--stall MIN]`, the view that stands in for the engine's ListAgents, which the guide tells a session to use instead, and the one cheap line plain `list` ends with inside a session — the bridge's running count, else the open turns of the running process from their tails, never the deep reads; each subagent's lifecycle — running, waiting on background, stalled, orphaned, completed, failed, stopped — from the engine's word where the session's bridge answers (GET /agents, the engine list's `status` the bridge mod carries; an end older than a revival's open turn yields to the rows), else from the disk: the meta, the transcript's tail read backwards for whether its turn is open, what is in flight and since when, its background tasks through `sminos_jobs`' ledger, the TaskStops and stop notes of its parent loop and the main loop — read once a view, only back as far as asked, found by bisection on the rows' timestamps — and the session process's start, before which nothing still runs; its activity beside it; `--json` an envelope `{self, scope, counts, agents, notes}`, every note saying what could not be read), `sminos_requests.py` and `sminos_outcomes.py` (pending requests and their settlements, and delivery outcomes, as the hub's sealed messages), `sminos_policy.py` (the machine's policy and its known checkouts), `sminos_rpc.py` (the RPCs: their checks, the ledger, execution, and the outcomes that follow them — a compaction's, a desk command's run and a side question's answer as DX4 `op`, a `/reload-plugins` finished by its bridge answering from another child; a stop-agent's and a tell's answer is their outcome, reconciled after a stop from the child's kept answer as a steer's is; an upload's attachments' states as `op` too; plan `docs/doperpowers/plans/2026-10-15-desk-dc7-controls.md`), `sminos_media.py` (a desk upload's files, MW5: written under `<cwd>/.claude/desk-uploads/<session>/` through a walk from `/` that follows no link, each created exclusively under `<nonce>.<n>.<ext>`, the extension its bytes' signature names, a refused save rolling back only the files the upload made its own; the repository's common `info/exclude` given `**/.claude/desk-uploads/` through the same walk, a linked or irregular exclude refused; each root recorded at `daemon/uploads/<session>.json` before anything is written, and swept, again following no link, by the bridge kept file's rule), `sminos_codes.py` (the codes, pinned to the hub's vectors by `sminos/tests/codes_parity.py`), `sminos_archive.py` (the archive), `sminos_marks.py` (the to-human mark grammar, ported from `to-human/hooks/mods/to-human.tsx` and pinned by `sminos/tests/marks_parity.py`), `sminos_bridge.py` (the child the bridge mod spawns, serving the session's endpoint at `$SMINOS_HOME/bridge/<session>.sock`, and `sminos watch`), `sminos_control.py` (`steer`, `interrupt`, `stop`, `model`, `compact`, `command`, `read`, `decide`, `answer`, and a delivery's last hop to a live session: the bridge, else a `--bg` job's supervisor `reply` for a human's message, else the inbox frame), and the chart and TUI; a session the bridge mod runs in is watched and driven from any terminal on the machine with `sminos watch|steer|interrupt|stop|model|compact|command|read|decide|answer <member>`, its protocol DX5 in `docs/doperpowers/plans/2026-10-15-arkho-desk-c2-bridge.md`; tests `sminos/tests/run-sminos-tests.sh`, which isolate `HOME` and `SMINOS_HOME` — a working copy's CLI run against the real `~/.claude/sminos` performs the one-way import of the old per-host `chats/` on its first call; `sminos/tests/bench_scale.py` measures the daemon's tick, both daemon processes' CPU and an import burst on a synthetic machine at the owner's Macs' scale, against any copy of the scripts (before and after a change).
