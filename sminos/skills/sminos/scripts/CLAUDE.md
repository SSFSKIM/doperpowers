# sminos/skills/sminos/scripts/ — the sminos CLI, the daemon and its uplink

A path here is named from `sminos/` when it is the plugin's own file; `docs/`, `sminos/…` and `to-human/…` paths are the repository's.

With a remote in `.smns` the log is a git working tree mirrored through it, and `sminos daemon` (one per machine; `daemon install` writes a launchd agent on macOS, a systemd user unit on Linux) syncs the mirror, delivers remote messages to local members, and publishes their state, so a project spans machines.

A project whose `.smns` names a desk hub instead (`project init --hub`, on a machine enrolled by `sminos hub enroll`, which reads the enrollment code — it carries the org key — from a hidden prompt or stdin and refuses it as an argument; `hub show` prints the machine's identity, never a secret; the file names the org alone, `"hub": {"org": …}`, each machine's enrollment the hub's URL, as doperpowers' own `.smns` does) syncs through the hub alone, never through git: `daemon run` supervises `daemon uplink`, a child process holding the hub's stream, which uploads the machine's own writers sealed with authentication codes and verifies every event the hub sends before it enters the log, and the machine writes under its enrolled name. Over the same stream the uplink serves the desk's session plane and its RPCs, the daemon being the execution boundary: presence from the engine's session records, each subscribed session's transcript and its bridge's stream joined in one order, the bridges' pending requests and their settlements, and the outcome of each delivery of a message from outside the machine; presence carries what each session's bridge can do (`capabilities`), the permission mode it last read (`mode`, DX4's ModeReading `{mode, at}`: its child's status's `permissionMode` and `permissionModeAt` as the mod last posted them, the bridge's own reading, so the body moves only when the session reports a mode, never as the probe asks again, and an idle session's switch reaches it within a probe, `BRIDGE_RECHECK`; absent until the bridge has read one) and the machine's `desk` (its sminos version, its RPCs), a `read` frame is answered on its subscription from the bridge (an `mcp` read with the servers the session's project disables added: `projects[<key>].disabledMcpServers`, the one key read of the engine's global config, the file and the key chosen as the engine chooses them — the legacy `.config.json` while it is nonempty, and a linked worktree's primary checkout), and a desk command's run and a side question's answer go up as `op`, each only to a hub whose welcome lists its kind; an RPC (steer, interrupt, stop, answer, decide, model, compact — its instructions passed to the bridge —, command, btw, stop-agent and tell — one subagent the session's tree holds as running, by its id, else the name of exactly one running agent (`unknown-agent`, `ambiguous-agent`), the id it resolved passed to the bridge, which acts on that agent alone —, spawn, retire, resume, media — an upload saved under the session's live working directory and handed to its bridge, which reads it in by a Read of its own —, and on RL10 alone send — a person's message entered through the bridge's `deliver` under `{writer: rl10-send, seq}`, the seq reserved per session in `daemon/sends.json` as its frame arrives (above the mark the session's bridge kept, and above the file's `floor`, the highest seq of an entry a reserve dropped — hourly at most, a session gone with no bridge socket and nothing in flight — since the bridge's kept file is swept a day idle) and posted in that order, answered `{entered, uuid}`, `refused-delivery`, or `{submitted: true}` past 10 s (MAWS O9 §E) —) runs only once its code, the machine, project, and session it names, the at-most-once ledger (`daemon/rpcs.json`, keyed by the RPC's operation id — RL4's `opId`, which carries `opCreated` and is refused `expired` past `OP_HORIZON`, a day less an hour, so pruning never reopens one; else its nonce, as DX6 sends it — the hub's `rpc-result` and `rpc-ack` keeping the nonce, an op's answer going up under its latest copy's, a copy that arrived while the op was in flight or claimed included; a tombstoned op refused `tombstoned`, and `query`/`tombstone` on the daemon's controller answering what became of an op, claim and tombstone one transition under one lock with the workers' `flight`; `sminos rpc-query [--created T] -- <opId>` prints the ledger file's view, without `flight` (`--` since a base64url id may start with `-`)), its age, the machine's policy, and, for an answer or a decision, the digest of the request still pending all hold (drawn from the input its raise carried, which for a permission past `RAISED_INPUT_MAX`, 256 KiB, is cut as the mod's resync cuts one and marked `truncated` — `sminos_requests.shown_input`, so no raise or complete set passes a lane's bound — or from the input whole; a scoped allow's rule, `decide.scope`, is resolved from that request's own suggestions, never from the browser: `session`, or the suggestion's own `localSettings`), and its result is sent again until the hub acknowledges it. The policy (`daemon/policy.json`, set by `sminos daemon policy [--read-only on|off] [--ceiling MODE|settings]`) can make the machine read-only — no RPC runs, nothing from outside is delivered — and caps a spawn's permission mode; Resume runs `claude --bg --resume <session>` with no other flag once no process of the machine holds the session, and stops any copy the engine starts instead; a session whose record's controller is lane B is refused `lane-b` (reopening a MAWS lane B session is MAWS's), as is any op an observer's bridge refuses `lane-b`, a refusal its child kept and a restart reads back included. Such a project's remote keeps only the log's archive, which the one machine the hub designates for it writes on a schedule (`SMINOS_ARCHIVE_EVERY`, 15 minutes) from a clone at `projects/<id>/archive/`, never read back into the log.

Every enrolled machine follows every project of its org (the hub's `org` frame, kept at `daemon/org.json`), so `sminos list --org|--here|--project|--machine|--state [words]`, `find`, `projects` and `machines` show who works on what across the org, and `@short`, `@alias#short` and `@<project>/<alias>` reach any session there, recorded in both projects' logs (a bare `@alias` stays in the sender's project); design `docs/doperpowers/specs/2026-10-18-smns-org-directory-design.md`. Another machine's member reads its last published word, but `gone` once the directory retires its machine (`machine_retired`: its `machines` entry `retired: true`, as RL10's endpoint marks a machine no certificate stands for any more, or its machine project retired, as the hub retires a revoked machine's; by name, lower-cased), which `machines` shows `retired`. On a cut-over machine `machines` claims no presence, which RL1 does not carry (the endpoint sends every machine `online: false`, and `seen` only as of its last restatement): this machine is `this machine`, another its newest event, the frame's `seen` or the logs' (`newest_events`); and the directory's age line says the endpoint restates it only when the org changes or the daemon reconnects, where on DX2 an old one means a silent stream.

A machine whose MAWS `mawsd` endpoint serves RL10 is taken off the network by it (O12 phase 2, M5; plan `docs/doperpowers/plans/2026-10-27-p5-o12-sminos-owners.md` in MAWS, the frames O10's Interfaces §D). `sminos_rl10.find` reads the endpoint's `rl10.json` (`$MAWS_USER_DATA/mawsd/endpoint/`, else O2's platform default; `SMINOS_RL10` for a test): a regular file of mode 0600 owned by this uid, protocol 1, a token of 64 hex characters and a socket, anything else no endpoint, said once in daemon.log. Before the cutover `daemon run`'s supervisor only probes it, beside the hub's uplink and never in its place (`sminos daemon probe`: dial, `hello` with the token, the welcome; backing off from 1 s to a minute, from 1 s again when rl10.json changes): a refusal, a wrong token, silence, or a welcome whose identity is not whole (org, hub, name, ref and enrolled: an endpoint not enrolled yet, which `daemon status` says) leaves the hub's stream as it is. A whole welcome cuts the machine over, once and for good: `daemon/identity.json` (0600; org, hub, name, former, ref, enrolled, cutover, build; `former` this machine's own map of names to the sessions held under them, copied from hub.json at the first welcome, a rename the endpoint made adding `sessions_under(old)` before the replace, and never shrinking) is read before hub.json by `enrollment`, `machine_identity`, `enrolled_at`, `hub show` and `project init --hub`; the hub's uplink is stopped, and the child (`daemon uplink`) speaks RL10 alone from then on — `Link` with `coded` off over a `SocketTransport` (the reader, and one `SocketLane`: newline-delimited frames of at most 1 MiB, DX2's parts beyond; a frame written is taken, its continuation run on write, everything restated after each welcome and closed by `restated {}` once the whole restatement is queued — the member set, every hub project opened with its presence, pending set and unacknowledged results, the host events owed again (`Link.restated_due`) — since at `restated` the endpoint withdraws every session it left out; every session kind sent) — and while the endpoint is not running nothing runs (`daemon status`: `cut over; the endpoint is not running`; daemon.log at once and hourly). `hub enroll`, `check` and `leave` exit 1 there, the enrollment being the endpoint's, and none dials the hub; removing identity.json undoes the cutover, in O14's order: the endpoint out first (rl10.json and its socket gone), then identity.json, after which the supervisor runs DX2 from hub.json, or nothing with none — identity.json removed while rl10.json is still served is cut over again by the next probe, at a new `cutover` time (test-uplink.sh pins both orders). The endpoint's `policy` (the welcome's, and each frame) is the machine's: written to `daemon/policy.json` with the endpoint's last word kept beside it (`endpoint`), so a `daemon policy` change made here goes up as `policy-set` and the file settles on the answer, and a welcome never overwrites a change it was not yet asked for; on the wire (`hello`, `presence`, `policy-set`) a ceiling the file does not name is RL10's `"settings"` (the settings' defaultMode: `sminos_policy.wire_policy`), and an endpoint's `"settings"` leaves the file without one. O10's RL10 conversation (MAWS's `test/endpoint/rl10/conversation.json`, copied byte for byte to `sminos/tests/rl10-conversation.json`, its commit and blob in `rl10-conversation.source.json`) is replayed against this uplink by `sminos/tests/rl10_conformance.py`, every line as written: a line sminos cannot send as the fixture has it fails. Its revocation sets go to `daemon/revoked.json` (0600; whole from the first after each welcome, merged into after, never by an older version; `sminos_rl10.revoked()` raises rather than read an unreadable file as empty). `legacy-key?` is answered from hub.json's key, to an endpoint welcomed for the key's own org only, as often as it asks, and the key is in no log line. On RL10 nothing carries a code and nothing is sealed, verified or indexed by nonce (the key is None): `HubLog(..., coded=False)` uploads this machine's events as stored (`ts`, no `mac`, no `created`, which the endpoint derives from `ts`), and takes each arriving event wrapped `{event, signer, owners?}`, the shape checks as on DX2, one whose `event` carries `verified` refused `bad-shape`, the rest stored verbatim with `verified: {signer, owners}` added (`owners` only when sent, as `{id, email}`); an own event the endpoint returns, `created`, `sig` and `attest` added, reads `present` when it echoes the stored one, else `conflict` (`same_uncoded`). An arriving event the endpoint refused for good never comes down; its position does, `spent {project, writer, seq, reason}` (O12 M7b), recorded as a position refused here (`HubLog.spend`: an own writer's, under this machine's name or a former one, through `spend_own`, so a position an event of this machine holds stays that event's and is said, not spent; the writer's later events not held behind it, the vector past it), each said once in daemon.log with its project, writer, seq and reason, and counted per project by `daemon status` on a cut-over machine. `raised`, `settled`, `pending` and `delivery` bodies go as drafts (`Requests.seal`, `outcomes.message` with no key), settlements the hub's uplink left owed in `requests-owed.json` too (restored without their `mac`). A welcome that renames the machine renames the requests and the RPCs in place (`rename`), never replacing them: each is the one owner of its file under `daemon/` and of the workers that write it. `Rpcs(..., coded=False)` skips the code check alone; its entries keep the RPC's `member`, `device`, `fingerprint`, `context` and `proof` and a `target` derived from the checked RPC (`{kind: machine}` for a spawn, else the session); `rpc-result` names the `opId` beside the nonce, a loose refusal's too; `rpc-ack` settles by the nonce, else by the `opId`; the endpoint's `query` and `tombstone` reach `Rpcs.query`/`Rpcs.tombstone` and are answered `queried`/`tombstoned`, each with the op's binding (`member`, `device`, `fingerprint`, `target`: its entry's, else its in-flight record's; none for an entry an older daemon wrote). A remote action is bound to its sender and fenced to the launch it was sealed for (O12 M7). The binding and the latest nonce are the op's in-flight record from dispatch on (`Rpcs.flight`, under `op_lock`), and the claim or a refusal the worker keeps is built from it; a copy of a known or in-flight op from another member, or under another fingerprint, is refused `op-conflict`, loose, under its own nonce, saying nothing of the op; an identical one takes the nonce. An RPC on a session carries `context {lane: 'A', session: args.session, launch}`, else `bad-shape` at admission; `plan` adds the launch to every bridge command and decision (`fence`), which the bridge's child refuses `409 launch` when its own differs, before the mod sees it (the RPC fails `launch`; an upload so refused saves nothing); a remote RPC on a session with no bridge is refused `context`, never the supervisor's reply or the inbox, and `resume`, `retire` and `stop` (O10 offers none of them) `unsupported`. A remote spawn's `proof` goes to its verb as `SMINOS_DESK_PROOF` (canonical JSON), which the new session's record keeps as `ownersProof`. The DX2 path carries no context, binding or proof, and runs as before.

On a cut-over machine the endpoint decides a person's words from what sminos tells it (O12 M6). The uplink sends `member` for every session of this machine in every project known here, relayed or not (`Link.members`, from `Plane.member_rows`: the record's owners, proofs, origin, principal, inference and controller — `@machine` and `terminal` while it has none —, the lane, B by the controller or a `maws` origin awaiting one, and the row's alias, state, title, cwd and worktree, and `launch`, the launch its bridge's status names, kept by the plane's probe, which a cut-over machine's presence carries beside `bridge`), the whole set after each welcome, then each change, `{session, gone: true}` at leave. The endpoint signs an upload as its frame arrives and attests it from the record it holds, and keeps that signature, so the member set goes first in each tick, ahead of every hello, upload and host message, queued in entries of at most 256 KiB and none while the lane holds 4 MiB unsent (a frame carries the record's proofs, which a lineage inherits), nothing that depends on it going until all of it is queued; and the sessions a drawn upload frame carries, a host pass's and the words asked have their frames queued first with their records as they are now (`Link.members_before`: a session that joined since its project was last read is looked for in the project's rows, once per listing; a frame whose member cannot be queued yet is drawn again on a later pass). Every `human` event `_append` stores under this machine's own writer gets an append receipt first, under the writer file's lock (`projects/<id>/receipts/<writer>.jsonl`, `{seq, hash}`, the hash over the stored canonical body; outside `log/`, so never mirrored or uploaded; kept under the writer name used): the writer name is not provenance, a git mirror's merge can bring a `<thisname>/human` line, and only `receipted` events are an own operator's. A revocation set marks every owed event its signer (`verified.signer`: key id, device or member, `sminos_rl10.signer_revoked`) names, asked or not (`revoke_owed`, `delivered_revoke`: the delivery record's `revoked` seqs, its `refused-revoked` outcome recorded first; never delivered, `_owed` leaving it out, and passed by the settled prefix only in order, since a member's devices share `hub/<member>`). Who delivers a person's words there (`words_route`): a `human` event of `hub/<member>`, of another machine's `<name>/human` that arrived with `verified`, or of this machine's own `<name>/human` (a current or former name) whose receipt matches is the endpoint's to decide — the uplink's words pass (`Link.ask_words`, after the tick's upload pass, so an own event has gone up on the socket before it is asked; at a nudge, an import, a verdict, a welcome or an ask's deadline, else every 10 s) sends `words? {id, project, session, event}` (`project` the log that holds it, which the endpoint requires; the stored line less `verified`) for the first owed event of each such writer of each local member in every project known here (`words_due`), queued in entries of at most 256 KiB and none while the lane holds 4 MiB unsent, so a broadcast to many sessions is asked across passes, each ask held, its deadline counted, from when it is queued, and carries out `words {id, verdict}` at once (`deliver_verdict`, under the delivery lock and only while it is still its writer's first owed: `words` the bridge, then a --bg job's supervisor; `peer` the inbox frame; `refuse` nothing, settled `refused-words`); unanswered within 10 s it is a failed attempt (`words_unanswered`, toward the 60 a push has) and is asked again under a new id, and a revocation drops its ask. Every other deliverer (`deliver_next`: the daemon's tick, `say`'s fast path, the uplink's delivery of what it imported) stops such a writer at that event (`gated`: `say` prints `recorded; the endpoint decides its delivery` and nudges the daemon, whose uplink asks), and delivers the other `human` events — a git mirror's, an operator line no receipt bears out (both said in daemon.log), a legacy signer's — as peer messages, never asked; an operator's `send`, to a seat or a seatless session, is recorded and pushed nothing (`SendDelivery.held`: `recorded <ref> for <alias>; the endpoint decides its delivery`); and `push_live` raises rather than decide a log-backed `human` event by its writer with no verdict. Every deliverer checks an event that carries `verified` against `revoked.json` before it pushes it (`WordsGate`, the set read again for each event, so a revocation kept mid-batch stops what follows): a revoked signer's is marked, and while the set cannot be read such an event waits. A session's `send` checks every earlier event of its writer it carries the same way (`SendDelivery.checked`): a revoked one is marked and left out, the valid ones go with it, and one the unreadable set cannot clear holds the send owed (`recorded <ref> for <alias>; it waits behind <ref>, …`). A chat frame, a `send`'s frame (`[sminos message from <sender><label> id=<id>]`, the id `send --wait` looks for unchanged) and a `sminos chat` line carry the label after the sender, from `verified` alone (`sender_labels`): `, owned by <email>` (the id where the endpoint had no email), ` (owners unverified)`, ` (unverified, legacy)`, ` (signed by a revoked key)` however old the event, and ` (unverified)` for an operator-writer event no receipt bears out that is later than the cutover (identity.json's `cutover`: older history reads as before, though delivery still never takes such an event as words); nothing on a machine not cut over.

What a session sends its person stays on a cut-over machine (O12 M8): `append_host` puts the host events (`message`, `question`, `answered`) of its own project and every hub project in the host store, `projects/<id>/host/<writer>.jsonl` beside `log/` (`host_store_holds`; the log's event shape and writer names, the store's own seqs, the `(kind, src)` rule, an answer under its asker's writer, a question found in either store; the route, and the check against what the writer's log took before the cutover, decided under that log file's locks, so two exports of one event on either side of the cutover leave one copy), never in the log the hub carries, and git-mirrored and local projects keep them in their log; the log's host events from before the cutover stay where they are, and `chat --host` merges both by time (`host_read`). The uplink's host pass (`Link.host_pass`, RL10 only) sends each up as a sub-less session-lane `host` message, body `{id: {writer, seq}, event}`, whether or not anyone subscribes (the endpoint derives its `wrote` notification from these), past the project's cursor in `uplink.json` (`host_sent`, moved once written), and each session's last 50 again whenever a connection opens the project, queued in entries of at most 256 KiB and none while the lane holds 4 MiB unsent, so a backlog goes across passes; a main subscription carries the session's host events in its own stream (`host`) and its snapshot (`host`: the last 50, `sminos.host_events_of`). Nothing of `host/` is in the vector, an upload or a resend.

`sminos daemon owed` (O12 M7c; O14's B2 reads it before a machine cuts over) lists what this machine still owes, one line a project with the counts, the oldest item's age and at most three references a kind, never a body, and exits 0 only when nothing is: `deliveries` (owed to a session joined from here, by its delivery record), `words` (those a cut-over machine's endpoint decides, asked or not: the asks out are the uplink's memory), and, for a project of this machine's upstream (a hub project of its enrollment's org), `upload` (the writers the uplink uploads — its name now, and `legacy/` while it writes the archive — past `taken` in the project's `uplink-taken.json`, the uplink's own view of what it no longer has to send and never more than its resume state: each opening `have` sets it to what the upstream holds, down as well as up; each upload answered and not refused whole — on RL10, once written — and each later `have` raises it; a writer the hub or the endpoint refuses, or asks again for (`resend`), is lowered and bounded for the stream (`HubLog.bound`): an upload sent before the bound takes nothing when its answer comes, a later `have` does not pass it, an upload sent after it resolves it), `queued` (the operator writer's appends that wait for the upstream's head of it, below), `refused` (the positions there where the upstream holds another event, from a `conflict` refusal: nothing in the uplink resolves one — a reconnect uploads the writer again and is refused again, and `spend_own` spends only positions no own event holds — so they are kept in the same file past the stream, cap `taken` below them, and leave only when the upstream's echo of this machine's own event there reads `present`; the owner looks at one before a cutover), `kept` (requests-owed.json but what requests.json says was relayed, and rpcs-owed.json; aged by the file's last write), `host` (the host store past `host_sent`, under its name now or a former one, as the host pass sends) and `outcomes` (outcomes.jsonl). A state file it reads that is there and cannot be read as one — identity.json or hub.json, a project's registration, a log or host file, a delivery record, uplink.json, uplink-taken.json, outcomes.jsonl, a kept file unreadable, not JSON or another version's — is no evidence: it is named on a line of its own (never a byte of it) and the exit is 1; only an absent file reads as nothing kept. Events owed to a closed terminal session (`sminos_outcomes.closed_sessions`) are a line of their own and owe nothing. The uplink's writes of uplink-taken.json are best effort, never stopping the frame in hand (a `resend` is followed whatever the write does); one that would have lowered it removes the file instead, so it never says less is owed than is. It only reads — no lock, no write, and `sminos.main` routes it before the migration — so it runs beside a daemon. `bench_scale.py run --rl10` times the uplink's words passes through `SMINOS_WORDS_TIMES` (a file each pass appends `{at, wall, cpu, asks}` to; unset, nothing is timed) and checks B2's gate.

An enrolment can name a machine under a name the upstream already holds history for (a VM recreated under its old name, `hub enroll --replace`, the endpoint's welcome at a cutover or a rename): its session writers are new UUIDs, but its operator writer, `<name>/human`, would take seqs from 1 that the upstream holds, never uploaded (the uplink's `sent` starts at the upstream's head) and a fork of the log (#147). So `hub enroll` and a welcome that cuts over, renames or re-enrols add the enrolment (its name and `enrolled`) to those `daemon/heads.json` marks before the credential or identity they publish, the one it replaces kept marked, and while the enrolment now is marked an append to that writer in a project of the upstream waits in `projects/<id>/queued/` (`sminos.waits_for_head`; `_append` returns it with seq None, and `say`, `send` and the line verbs say it waits) until `HubLog.release_heads` sees, after a `have`, an import or a spent position, that the log has reached the head that `have` named — the hub's backlog imported on DX2, the positions the endpoint refused spent on RL10; the project's `heads.json` then names the writer known for the enrolment, and what waited — under its name now or a former one, should a welcome have renamed it meanwhile — is appended above the head under its name now, in the order it was said (`sminos.said_order`: each queue in its file order, the queues merged by ts, a former name's first on a tie, since the rename came between), with the ts it was said at, receipted, uploaded and delivered. A machine that leaves its upstream before that (`hub leave` before the first `have`) keeps what waits queued: appending it could take a seq the hub holds, and an enrolment under the name again releases it; `hub leave` names it per project, and `daemon owed` counts it in any project, upstream or not. A machine enrolled before this has no mark, and nothing of it waits.

Each session sminos joins has a record of its own on the machine (O12 M1, the remote layer's RL6; plan `docs/doperpowers/plans/2026-10-27-p5-o12-sminos-owners.md` in MAWS), kept by `sminos_records.py` at `$SMINOS_HOME/session-records/<session>.json`, mode 0600: its `owners` (member ids, or `@machine`: this machine's owners, a token RL10's endpoint resolves against the org state), `ownersProof`, `origin` (`terminal`, `maws` with its `requester`, or `sminos-spawn` with its `spawnerSession`), `principal`, `inference` (a config-dir slot, or a route naming a file or a gateway's `base-url:<scheme>://<host>[:<port>]`, never a secret), `created`, `former`, its `basis` — the evidence it rests on, strongest first: `launch`, `lineage`, `hook`, `default` — and `source`, the basis when that evidence is final, else `default`, provisional. Every path that joins a session makes sure of its record first (`sminos.ensure_record`), and a record is replaced, its `controller` kept, only by strictly stronger evidence (the basis's rank, then final over provisional), so equal evidence read twice never flips it; the owners an owner's `record.owners` act added (a member whose act adding it is in `ownersProof`, `sminos_records.added_by_acts`) are the session's current state, as its policy is, kept after the replacing provenance's owners (`_record`), and with them every proof of the record replaced that the provenance's lacks, in its order after the provenance's: MAWS's attestation check verifies an add only when its signer is a machine owner or proven by an earlier proof, so the chain behind the act is kept, the members it proves not made owners again; so an owner added while the record was provisional or weaker is not lost to the evidence that replaces it. A spawn's provenance is fixed before the child exists: `spawn_fresh` writes `session-records/pending/<launch>.json` and launches with `env.SMINOS_LAUNCH` in the merged settings file it now always writes; the child's first SessionStart, a startup, binds the launch to its own session id with no lock (`pending/<launch>.session`, created whole by a link) before the hook does anything else (`claim_launch`, ahead of the migration), and its hooks claim it by one rename until one succeeds, as the spawner may once the harness names the child, the claim honoured for the bound session alone, so a `claude` the seat's Bash starts, inheriting the variable, claims nothing even when the seat's claim waited out a held lock. A continuation's is its lineage's, its predecessors' alone (its own publications are never evidence): the first final record along it (`hand_off`, the `continued` retirements, a job's live predecessor), else the latest `joined` among them that publishes, else the first provisional record. The hook's or the bridge child's reading of the session's own environment (`hook`: `maws` when its host marked it, the route from `ANTHROPIC_BASE_URL`, else the slot from `CLAUDE_CONFIG_DIR`) speaks only for a session no launch and no lineage speaks for; else the machine's defaults. A marked session MAWS's engine host launched for a remote member also carries `MAWS_LAUNCHED_BY` (O12 M11: its `appSessionId`, the spawning `member`, `device` and `opId`, and a `proofFile` holding the sealed spawn action): its hook record is that member's (`owners`, `principal`, `origin.requester`), its `ownersProof` the file's action when the envelope's member, device and opId and the action's device and opId match the variable (else `[]`, said in daemon.log, the owners unchanged), but only for the first session of the `appSessionId`, bound by a link-created `session-records/launched/<sha256 of it>.jsonl`; a later session there (a `/clear`, a resume into a fresh session) is appended under its lock and continues the latest before it, so an owner change carries over and the variable never grants the spawner again over a record (it is the fallback only while none of them has a record file). An idle daemon looks again only at what can have moved, since a machine's history (hundreds of own writers of ended sessions, every project of its org, logs of tens of thousands of events) is what its polls used to re-read (2026-10-28: the uplink at 5–16 % of a core, `daemon run` at 4–7 %). Between scans the uplink's upload pass looks at the hot own writers alone — a running session's, the operator's, one that changed or whose session ran within `HOT_FOR` — and lists a log directory again only once its mtime moved, a listing kept only once the directory held still `RACY_NS` before it (a coarse clock), and none that failed (glob takes a failed listing for an empty directory); every scan, nudge and words pass, and any look that listed again, is whole (`HubLog.writers`, `own_paths`). A scan reads within the cache generation the session plane renews, forgetting every cache only at a nudge or a welcome. The plane reads a project's members at `MEMBERS_EVERY` only once what that read draws on moved — the log's files, the seats, its members' engine and session records, the internal forks (`Plane.stale`) — every project when a session came or went and at `MEMBERS_WHOLE`, and RL10's member reads of the projects not open on the stream take the same rule; a member read runs in a cache generation renewed after its inputs were taken, so RL10's, which come before the plane's tick, renew it first. Machine presence draws a project's checkouts from the plane's last read (`Plane.here`), every `CHECKOUTS_EVERY` and at the first scan after that read moved the directories its sessions joined from (`Link.draw_machine`): the checkouts also decide whether a project is held or followed. A whole read of a log is merged, and `view_of`'s projection made, again only once a file of it moved (`_store_whole`, `_PROJECTED`; each reader still gets copies of the events, but for a View, which is read-only and shares the merged list).

A quiet tick of `daemon run` writes nothing (sminos 1.27.11; on a copy of the MacBook's state, 88 projects and 56 k events, it had renamed all 84 project records changed only in their stamp, tried 193 mkdirs and made 1,100 opens, 0.147 s of CPU every 5 s). A project's record (`daemon.json`) is written only when what it holds changed — the tick's result, its error (a failed tick's too, said once in daemon.log while it stays the same), publish_state's candidates, the former writers said, the archive's last run — and its `tick` is when it last changed; the end of every tick is the mtime of `daemon/ticked` (one utime: `daemon status`'s last tick, and what a test waits on). What a tick reads again every pass is read through `sminos.file_bytes`/`json_at`, a stat while a file's inode, size, mtime and ctime hold (each is written whole, by rename; a chmod moves the ctime, so a file made unreadable fails as it would have): the registrations, the project and session records, the delivery and `recorded/` records, the join overrides, the policy and the settings, hub.json, identity.json and org.json, a bridge's kept file, and the .smns, git config and HEAD a resolution reads. What is derived from a log — its addressees, its memberships, the lineage index, the late former writers — is kept beside the merged list until a file moves (`log_memo`); the seats' projects are taken once a cache generation (`_seat_pids`) and the internal forks once for each read of the engine's records, listed after it (`internal_pids`: derive marks a fork before its engine can start), and the registrations' roots once for `remote_moved`. A closed session's outcome report takes the delivery lock only once a look without it finds something to report (`sminos_outcomes.owes_report`: what is settled and reported only grows), the bridge directory is listed once a generation, and the next derivation is looked for only once one can be due. A git-mirrored project's tick fetches and looks at the refs (two git processes where it ran fourteen): when the remote's main, the local branches, HEAD, the work tree (by stat), the config and the claim are as the last sync left them settled — committed and merged, HEAD's branch at the remote's main by the very refs kept, the tree seen clean under the appenders' `.sync.lock` (`sync_out`, `_SETTLED`) — the claim's check, the commits and the merge are passed by, and the push phase reuses the look taken after the fetch. On Linux a process's start reads /proc/stat's boot time once a cache generation (a step of the wall clock moves it). Between ticks the loop's polls are a stat each — the nudge, hub.json (`credential_bytes`) — and an lstat of rl10.json, which `sminos_rl10.check` answers as before while the file's identity holds; nothing makes a directory that is there.
