# to-human/

A path here is named from `to-human/` when it is the plugin's own file; `docs/`, `scripts/` and `to-human/…` paths are the repository's.

A third plugin in this marketplace (versioned on its own: `scripts/bump-version.sh --plugin to-human`), the report view of a session under the `to-human` output style. It is a plugin of its own because the engine runs none of a plugin's render hooks on a row that plugin submitted (the debug log's `ui.render skipped: re-entry (the plugin's own code raised it)`), and sminos submits prompts (the bridge's sminos deliveries, the ask's answers) as doperpowers does (the compact mod's resume prompt).

Its `plugin.json` lists sminos under `dependencies`, which installs and enables sminos with it; its place outside sminos and doperpowers comes from the owner's `prependPlugins` (first in the list, outermost), since a dependency alone puts the dependent outside its dependency only where both share a rank and pushes the depended-upon behind every plugin nobody depends on, so it sees the ask mod's rows before the ask draws them; its band above the prompt draws its line under what the ask's band draws there.

`hooks/mods/message.tsx` registers the message tool, `mcp__to-human__message` (input `{text}`, Markdown; result `sent`; its description only `Send the human a message.`, since when to use it is the style's rule): a message sent before a tool call, which written as text there comes back from the API (claude-opus-5-5, claude-fable-5-1) as a progress note's paraphrase that reaches no one, while a tool's input is never summarized; registered at an interactive session's start only under the `doperpowers:to-human` output style (read from `$.config.list()`'s `outputStyle` row, once) and never under `MAWS_NATIVE_TO_HUMAN` (MAWS registers its own `mcp__maws__message`), always loaded (`isDeferred: false`), a subagent's call refused (#310 is the ticket for letting one message the human), an empty one too; its name, input, result and the log event sminos writes for it are a contract MAWS and the desk build on (design `docs/doperpowers/specs/2026-10-20-to-human-message-tool-design.md`).

`hooks/mods/to-human.tsx` is the consumer of the `to-human` output style on every surface (`<message>`, with old `<to-human>`, `<essential>`, `<need-input>` and `<insight>` marks read as aliases of it; tags in inline code or fenced blocks stay literal; a message-tool call draws as a message where it sits, in the full transcript as in the report (the engine's row there is its input as one dim, cut line), its input drawn as it streams and never as raw JSON, its result as nothing, a refused or errored call left in the working record; an assistant message draws as its marked spans, each body a `Markdown` element on every surface (a render answer to a remote surface carries one props and only the first engine node draws there; on the terminal the engine's block carries its row margin between label and body), and the view's rows stand a line apart as the engine's do; a run of working record — unmarked messages, tool calls and their results — between two rows the human reads folds behind one `[ working record ]` button; a question asked through `AskUserQuestion` or the ask mod's tool stays in the report, and so do agent spawns through `Agent` or `Workflow` and the notification that one failed, and an API error in the main conversation, at the turn's end or mid-turn (sent and received agent messages, the other finish notifications, and a sminos delivery whose frame names a sender other than `human` fold into the working record); an API error is the row the engine writes in place of a response, known live by its append naming `<synthetic>` as its model (`No response requested.` excepted) and from the transcript file by its `isApiErrorMessage` flag, read with the rows' places, and a mid-turn error's row branches off the conversation's chain, so a resume draws none; buttons unfold a run, a message, or the whole transcript, and a `[ fold to report ]` press brings the folded run's button into view when that row's top is out of the window (each row's last `onScreen` says; a reveal, even one that moves nothing, stops the transcript following its bottom); a module that starts over (an update the reload applied, a `/reload-plugins`) reads, before its first answer, whether the conversation holds a mark and where the transcript's rows stand (its file found by the session's id, searched by rg where the machine has it, else grep), under the `session.start` each load raises, the rows waiting on it only while their own dispatch stands and at most 3 s (the engine holds a draw's budget at 10 s and unloads a plugin whose draws twice run past it deaf to their signal, which a 437 MB transcript's grep did on 2026-10-20), since the fullscreen transcript holds a row off its window at the height it last had and lets go of it at the window's top edge, so a row folded while off the window pulls the view down as it scrolls back in (the rest is the engine's, TECH-DEBT); on the terminal a span's link to a local file, `[name](/abs/path#L42)`, draws behind a file glyph as a `file:` link, and a plain click on it opens VS Code at the line, a cmd-click staying the terminal's).

`hooks/mods/notify.tsx` tells the person when a message is sent: each main-conversation response row whose text carries a `<message>` span (read by the view's own `parse`, so a quoted mark stays quiet) raises `$.ui.notify` with the first message as one line, as the row is kept, mid-turn as at the turn's end, and the message tool's handler raises it for an accepted call (never from the call's row, kept before the call runs), except in a sminos internal fork (`SMNS_INTERNAL`); their `Notification` hooks read it as `plugin_notification`, then their `preferredNotifChannel` writes it.

System notices (`Prompt dropped by a hook: ...`, a plugin's `$.ui.log` line) draw through no render hook of any plugin, so neither view can hide one once drawn, and a resume draws each again; which is why the reload mod tells a reload that went through by a toast, not a line.

Tests `to-human/tests/mods/run.sh` (the `to-human-mods` gate).
