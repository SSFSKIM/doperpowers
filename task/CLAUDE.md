# task/

A path here is named from `task/` when it is the plugin's own file; `docs/` and `.github/` paths are the repository's.

A sixth plugin in this marketplace (versioned on its own: `scripts/bump-version.sh --plugin task`), the `task` command: the agents' one command for tracked work, which today works tickets on a repository's GitHub board. Design, decisions and the milestones still to come (the relabel, claims, the skill, sminos's calls): `docs/doperpowers/specs/2026-11-24-ticket-board-design.md`; what follows is how the code meets it.

- `bin/task` runs `cli/main.py`, Python 3.9 and the standard library only; it imports nothing of doperpowers or sminos.
- `cli/config.py` decides which board a command works: the repository of the clone's designated remote (`git config task.remote`, else `origin`), read from its URL, configured by `.doperpowers/board.json` on `refs/remotes/<remote>/HEAD` (that exact ref, `git show-ref --verify`) as last fetched, never the working tree's copy; `--repo owner/name` reads that repository's default branch on GitHub instead. A board whose file is missing, names another repository or says a binding other than `task` is refused before any call to GitHub. It makes no fetch.
- `cli/github.py` is all GitHub access: `gh api --hostname github.com` with the repository in every call (never `gh issue`, never `{owner}`, never a host `GH_HOST` names), GraphQL operations named `Task…`, label writes as single adds and removes. A comment's id is read as `fullDatabaseId`: comment ids pass 2^31, beyond GraphQL's `Int`.
- `cli/record.py` is the record block (`task-record`, the body's last fenced block) and the body digest; `cli/board.py` the label vocabulary and a ticket as the reading verbs print it, trust and takeability included; `cli/lint.py` the lint; `cli/sminos_client.py` what `task` asks sminos (`TASK_SMINOS`, then `PATH`, then the marketplace clone; 30 s a call; anything but a well-formed answer is no answer); `cli/verbs.py` the ticket verbs (the claim verbs and `close` are below).
- `board.CROSS_REPOSITORY_BLOCKED_BY` says whether `--blocked-by owner/name#n` is taken: `live.sh edge` found GitHub keeps such an edge (2026-11-27). Were that to change, setting it False makes the CLI refuse such a blocker and say the wait is prose.
- A body file is prose: one that opens a `task-record` or `task-claim` fence is refused, so a record's keys are written only by their flags and verbs, and a claim record only by the claim verbs. Between prose and block the CLI writes exactly a blank line (`record.SEPARATOR`) and takes exactly that away with the block's last key, so a change of the record alone leaves the prose's bytes as they were.
- `cli/migrate.py` is the one-time relabel (`migrate plan`, `migrate apply`; D6, §8), `cli/legacy.py` what the old board left in a body: the trailing `board:meta` block, found as the old scripts' `meta_match` finds it (ported, not imported) and rewritten as visible lines, a pinned `plan:` becoming the record's `spec:`; and the retired service's mirror header, matched by its exact lines with the service's address matched by form, so no host is written here. `plan` resolves only a repository (no board file is read) and writes its file mode 0600, refusing a path inside any git work tree (default: `$TASK_HOME/plans/`); decision rows carry a `question` beside §8's keys. `apply` reads each row's issue again and takes up only a state the write order leaves (`_on_the_path`); a failed write stops its row, not the apply, which then exits 1, and its summary counts the writes it made (`writes: 0` on a rerun).
- Claims (D3): `cli/claims.py` is the claim record (`task-claim`, a comment's first fenced block) and the fold, which every reader computes alike over the trusted records of the ticket's open interval (a record dated the second of the last reopening is outside it); `board.Ticket.holder` is the fold's, and no verb reads the `claimed` label to decide. `cli/index.py` is the machine's index (`$TASK_HOME/claims.json`, §7, plus a `running` mark per board): one file, atomic replace under a `flock` held across read and write and never across a call to GitHub or sminos; a caller finds its row again by its attempt token. `cli/settle.py` is settle, `converge` (the label written from the latest read, one look, one correction) and `write_release` (a release confirmed like a claim: void at its place, deleted). `cli/claiming.py` holds the verbs: `claim`, `release`, `takeover`, `close`, `held`, `settle`, the settle `list` and `claim` run for their board first (`auto_settle`: 20 s, skipped within `TASK_SETTLE_EVERY` seconds, default 600, of the board's last completed pass or while another verb's pass runs), and `retry_owed`, which every verb that writes to GitHub runs first for its own board's owed releases (only that board's: a verb aimed at one board releases nothing on another). `TASK_CLAIM_BARRIER` and `TASK_TRACE` are `claim`'s test seams for `live.sh race`, off unless set.
- Who holds, for `release`, `close` and `takeover`: where the index has the claim's row, the row's thread (asked of sminos for the calling session), or for a row with no thread its session; the record's address only where the machine has no row.
- The contract with sminos, both directions (D5). `task` asks: `sminos who` (the address; none, and `claim`/`takeover` exit 1), `who --thread=<the session's own id>` at a claim or takeover before anything is written (taken only when `session` is that id and `local` true; `ended` true refuses), `who --thread=<a row's thread id>` at settle (only that very id, `local` and `ended` true releases; anything else, exit 4 included, is `unknown` with what it said), `who --thread=<name>` and `say` for `--to`. sminos calls (M6, nothing yet): `task held --session S [--thread T] [--cleared-from L] --json` and `task settle [--thread T] --json`, §9 of the spec, frozen at M3's review: both run from any directory, `held` reads the index only, and each exits 0 whenever it could answer. A call states nothing: settle asks about each thread itself.

Tests: `tests/run.sh` is the `task` gate, the CLI run as a process against `tests/standin/gh` (a `gh api` over a JSON state file, every call logged; its `hooks` play another writer at a chosen call, a kill of the calling process among them) and `tests/standin/sminos`, fixtures in `tests/harness.py`, every name invented. `tests/live.sh <case>` (`fork`, `edge`, `migrate`, whose Python steps are `tests/live_migrate.py`, `race`, whose are `tests/live_race.py`, and `lapse`, which spawns and retires a sminos thread) runs against real GitHub, on the private scratch repositories `TASK_LIVE_REPO` and `TASK_LIVE_REPO2` name, and is never part of the gate.
