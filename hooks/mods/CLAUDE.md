# hooks/mods/ — the doperpowers plugin's function hooks ("mods")

Bare file names are this directory's; other paths are the repository's. `register.tsx` registers the mods; `README.md` beside this file is their manual.

`fork-guard.tsx` holds the sminos bridge's fork agents (the session manager's `manager query`, design `docs/doperpowers/specs/2026-10-31-session-manager-design.md`) to reading: registered first in `register.tsx`, so its hooks are the plugin's outermost, it acts only on an agent `$.agent.list()` lists as `type: 'fork'`, `spawnedBy: 'sminos'` (the verdict remembered per agent id; an id the list does not name — a workflow's agent, the engine's own forks — passes, looked for again at its next call, and a subagent's call is refused while the list cannot be read), refusing at `tool.call` every tool but `Read`, `Grep`, `Glob` and `Bash` (decided by name, ahead of any user-tier plugin that serves its tool inside its own `tool.call` hook, and ahead of `Agent`, which the engine marks read-only), and at `tool.check` allowing the read tools and a Bash input the engine holds read-only and denying everything else, so a fork raises no permission prompt and runs no write; each registration's `.catch` refuses a call it had not passed on. The bridge spawns the fork from its command listener, outside every hook frame, which bypasses every sminos hook, so the guard has to be another plugin's; the bridge asks for it before each spawn with a `$.tool.check` query from sminos for a Read of `FORK_GUARD_PROBE`, which the guard alone answers `deny` with `FORK_GUARD_PRESENT` (both strings spelled the same in `sminos/hooks/mods/bridge-ask.tsx`), so a session without the guard loaded now gets no fork (`no-guard`).

`kairos.tsx` draws a `[ kairos off ]` / `[ kairos on ]` button in the prompt footer that runs `/kairos` or `/kairos off` on a click, reading the mode's state from the shell hooks and never writing it.

`compact.tsx` registers one tool the model calls, `mcp__doperpowers__compact` (the model compacting its own context at a checkpoint of its choosing), which the engine places behind ToolSearch, while the guidance on when to compact rides the plugin's MCP server instructions, in view from the first request on (a `prompt.attachment` hook puts it in place of the engine's line under `## doperpowers` in every loop's `mcp_instructions_delta`, about 1.7k characters: the engine caches answers process-wide by attachment UUID, which forks inherit, and reload does not await `session.start`, so the hook reads session surfaces, window and gate itself; a `tool.describe` hook kept the whole 2.3k-character definition inline until 7.207.0), and offers it at the main conversation's turn ends: at the `turn.complete` of a turn the model answered and asked no compaction in, the mod submits the context figures (the last response's input tokens, the compaction window, where the engine compacts on its own) and the offer as the plugin's prompt (`$.prompt.submit`), which the engine runs as a turn of its own once the session is idle, behind any prompt the person queued, and the model reads as "The doperpowers plugin sent a message: …" (the model compacts, or replies "Not compacting."; a prompt rather than the Stop hook's `additionalContext` it was until 7.192.0, because the engine draws a Stop hook's context as a gold `Stop hook feedback` row that no render hook reaches, while the to-human view folds a plugin's prompt and the reply into the working record). The mod's `prompt.submit` hook, matched on the plugin's own origin, knows an offer by its text, marks the turn it starts as the offer's (whose end offers nothing, so a gate of zeros does not loop) and reads the figures again as it enters, so an offer that waited behind a turn the person queued carries the context as it stands (after a compaction that stood meanwhile, or with no figure to read, it says there is nothing to decide, rather than being dropped, which would draw the engine's "Prompt dropped by a hook" notice); while one waits, no other turn end offers. An offer the engine removed from the queue gives its step back; one a hook beneath refused stays spent. The offer goes out from 300k tokens on and once the context has grown 70k since the last offer (`OFFER_GATE`; below 300k, `EARLY_BELOW`, which only a lowered floor reaches, the offer adds that compacting is not necessarily recommended unless at a clean checkpoint with nothing pending that needs the prior context whole; `DOPERPOWERS_COMPACT_OFFER_FLOOR` / `_STEP` override it for a launch, 0 and 0 being every turn) — each offer is a turn over the whole context, which is why it is gated. The offer's baseline resets when a main-conversation `session.compact` stands (not a skip or a `precompute`, which replaces no conversation) and when the mod's own compaction stands; a figure below the last offer's at any turn's end resets it too, even below the floor, as the backstop for an engine path that compacts without the event. An offer is withheld, without being spent, when a Stop hook beneath sets `preventContinuation` (a `classic.Stop` hook reads the settings hooks' answer and passes it unchanged), and at a turn that ended interrupted or on an error; the figures were a free tool, `context_usage`, until 7.184.0, retired for this push. The engine compacts only between turns, so the tool answers that the compaction runs when the turn ends and the model ends its turn; at the `turn.complete` of a main-conversation turn the model answered the mod calls `$.session.compact` (the `/compact` path: one model call over the live conversation, so the model that chose to compact writes the summary, the PreCompact hook's instructions merged in) and submits the `resume` prompt the model wrote, or, where the compaction did not run (skipped, failed, or found a turn begun: the engine starts whatever waits in its queue — a peer's message, the human's words through the bridge, a notification, the reload's command — before a turn's `turn.complete` hooks run, which no hook can reorder), what tells the model so and hands its request back, so an unwatched session never stalls and never resumes from a summary that does not exist; a prompt the person types over the turn after the call is held at `prompt.submit` until the compaction's outcome (unscreened at the queue's head, it keeps the engine from draining the queue), so it is answered on the compacted conversation, and a turn that ends otherwise lets it go; the wait is the hook's own time, so it ends just short of the engine's 10 s hook budget, and one sent longer before the turn's end gets the notice instead; nothing is aborted, so background shells, monitors, MCP servers and subagents run on (a `$.turn.abort` variant was rejected: it kills Monitors, whose shell runner gets no `caller` and so does not spare `turn-abort`). Interactive sessions only (headless has no compactor a plugin can call); a subagent's call is refused, and its turn end gets no offer. The engine hands every subagent every MCP tool and a hook cannot filter per agent, so the agent definitions this repo owns, and the user's own under `~/.claude/agents/`, withhold it through `disallowedTools`; built-in types (general-purpose, Explore) and forks still list them. The engine admits one unmatched registration of an event per module, and `$` may only be passed to functions in the same file, so the mod takes `session.start`, `session.compact`, `turn.complete` and `prompt.submit` with matchers (`isInteractive: true`, `trigger: /^/`, `reason: /./`, `origin: { kind: 'plugin', name: 'doperpowers' }` and `origin: { kind: 'composer' }`; `prompt.attachment` with `type: 'mcp_instructions_delta'`) rather than sharing kairos's, appeal's and interim's registrations.

`reload.tsx` applies a plugin update another process installed: the engine parses `installed_plugins.json` once per process and tells no other session of a new install (a `claude plugin update`, a roll, a new session's marketplace auto-update), so an interactive session stats the file every 15 s and, once a plugin it runs has another install path there, runs `/reload-plugins` through `$.command.run` while no main turn runs (the engine would queue it to the turn's end, ahead of a compaction the model asked for there) and no async ask's dialog is up (read from the sminos ask's snapshot, `{ plugin: 'sminos', key: 'ask' }` in `$.state`, which it observes; the ask mod keeps its asks across the reload, not a dialog), the machine's fetch is not applying a batch, and nothing the reload would load (a plugin carried by path loads at its clone's version) lacks a dependency, whoever wrote the records (read on the tick that would fire, and told once per hold in the transcript, naming the `/plugin install` that lifts it); one reload per state of the file, never `--force`, and one session per machine at a time (a `mkdir` lock and a stamp under `~/.claude/autoreload/`), at most every 5 minutes, compares each git `autoUpdate` marketplace's remote head (`git ls-remote`) with its clone and runs `claude plugin marketplace update` where it moved; a directory `autoUpdate` marketplace is read in place, with no remote query or marketplace update, installs every dependency the enabled plugins' manifests in the clone name that is not installed, and runs `claude plugin update <key> --scope <record scope>` for each enabled plugin's user and managed records whose version is not its clone manifest's (project and local records stay untouched); without a manifest version, git sources are checked when their remote moved, directory sources every round, leaving the CLI to decide whether to install, holding back any whose dependency chain reaches one that did not install, which the engine does only at a session's start. The rolling check includes the directory root, catalog, git index, HEAD and HEAD reflog as well as FETCH_HEAD and the parent directory, so an in-place reset after a fetch delays the round too; the lock, dependency hold-back and batch mark are shared with git fetches. Off with `DOPERPOWERS_AUTORELOAD=off`. The rows the engine keeps and sends for such a run (the caveat, the command line, the output) cannot be refused, so a `session.append` hook empties them, each then sent as `(no content)`, and the output's text goes to the person outside every request: a toast when it says no more than `Reloaded: …`, the plugin's `$.ui.log` transcript line when it says more (load errors, an unreachable marketplace, an update not applied); a `/reload-plugins` the person types passes whole (live check `tests/mods/live-reload-rows-check.py`).

`interim.ts` drops, at `prompt.submit`, an agent's task notification the engine marks interim (it stopped with a background shell, monitor or workflow of its own still running) when its whole result is the engine's waiting placeholder, the agent's transcript shows the hand-back contract on (so the engine wrote that sentence, not the agent; reached through the notification's own `<output-file>` link, so the hook keeps no session state, and searched with `grep`, past `$.fs.read`'s 4 MiB), and it tells the session nothing its conversation does not hold (the session's own loop spawned the agent or the conversation, read as it stands through `$.session.messages({ as: "api" })`, holds an earlier notice of it, and of any worktree it names), so a subagent parked on its own work no longer wakes the session for a turn with nothing to act on; a pointer to a delivered report passes (it can name a message that went to an ended parent), as do the first notice of each worktree and of each orphan, the final notification, and whatever a check errs on or cannot settle. Each drop still leaves the engine's "Prompt dropped by a hook" line, a system notice no render hook reaches.

`appeal.tsx` (with `appeal-judge.tsx`, the logic that takes no `$`) lets the agent contest an auto-mode classifier block: a `tool.call` hook on every tool gives each appealable block an id and a note (not `[Data Exfiltration]`, not `[User Deny Rules]`), `mcp__doperpowers__appeal` puts one appeal per block to an independent judge (`$.model.complete`, opus at high effort, reading the blocked call whole, the argument as the agent's claim, the instruction files, the `user`/`policy`/`flag` settings' `autoMode` and `permissions.deny` — never the merged settings a repository feeds — the answered async asks (the sminos ask's snapshot, whose growing `answered` count also ends every pass), and the conversations with provenance-stripped rows named), and a grant leaves a one-shot pass that the `tool.check` hook applies to the identical re-run in the same loop within 10 minutes (a main-loop grant is relayed — run by the appeal through `$.tool.call` on that pass — only when a `$.tool.check` asked first shows nobody would be asked, since a decider's verdict inside the appeal's own call can hold the session on a dialog the person never sees; otherwise the model re-runs it), only over core's plain `ask` (no rule, hook, setting, plugin, host approver or ceiling; `decider` on engines before 2.1.307); any `prompt.submit` ends every pass; the log is `~/.claude/appeals/<session-id>.jsonl` and `/appeals` prints the last 30 days with the autoMode entries the grants suggest, for the human to apply (design `docs/doperpowers/specs/2026-10-17-auto-mode-appeal-design.md`).

`/secret KEY` ships in the `cua` plugin (SSFSKIM/cua, `hooks/mods/secrets.tsx`), same store `~/.config/claude-secrets/KEY`; the guard that keeps secrets out of what the model reads and the transcript keeps is the devcloud plugin's (`devcloud/`).

Tests in `tests/mods/`, run with `tests/mods/run-mods-tests.sh` (the guard's `fork-guard.test.ts`; its live check is sminos's `sminos/tests/mods/live-ask-check.py`); the streaming hook's are `tests/claude-code/test-to-human-stream-hook.sh`; every plugin's mods and their tests are typechecked by `tests/mods/typecheck.sh` (the `mods-types` gate), against the declarations the engine lays in each plugin's gitignored `.claude-plugin/types/` as a session loads it from `--plugin-dir`, which `--lay` has the installed engine do headless.
